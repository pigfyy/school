Lecture 6 · Mon Oct 12

Same tree, three answers

\(T(n) = 2T(n/2) + 1\), \(2T(n/2) + n\) and \(2T(n/2) + n^2\) all draw the same binary tree of calls. Why are they \(\Theta(n)\), \(\Theta(n\log n)\) and \(\Theta(n^2)\)?

Look at the bars. With \(+1\) the work doubles on every level, so the leaves dominate and the total is about \(2n\). With \(+n\) every level does exactly \(n\) work, and there are \(\log_2 n + 1\) levels. With \(+n^2\) the work halves on every level, so the root dominates and the total is under \(2n^2\). That's the tree method: draw the calls, add up each level, then add up the levels.

Lecture 6 · slides 3–11 · Mon Oct 12

Writing a recurrence

Analyzing recursive code (slide 3). Pick a case (usually the worst). Count the operations in the recursive code and write a recurrence relation in terms of \(n\). Use the tree method to see the levels and the work on each. Turn that into a summation, then into a closed form.

// slide 4: recursive binary search
private static boolean binarySearch(
    List<Integer> lst, int k, int start, int end){
  if(start == end)
    return false;
  int mid = start + (end-start)/2;
  if(lst.get(mid) == k){
    return true;
  } else if(lst.get(mid) > k){
    return binarySearch(lst, k, start, mid);
  } else{
    return binarySearch(lst, k, mid+1, end);
  }
}
// slide 9: recursive linear search
private static boolean linearSearch(
    List<Integer> lst, int k, int start, int end){
  if(start == end){
    return false;
  } else if(lst.get(start) == k){
    return true;
  } else{
    return linearSearch(lst, k, start+1, end);
  }
}

The shape of a recursive function (slide 5). Do some non-recursive work, make one or more recursive calls on part of the input, maybe do more work. So

\[T(n) = T(p_1) + T(p_2) + \dots + T(p_x) + f(n).\]

Usually it's \(T(n) = a\cdot T\!\left(\frac nb\right) + f(n)\), called divide and conquer, or \(T(n) = T(n-c) + f(n)\), called chip and conquer.

Binary search does a constant amount of work and then one call on half the range: \(T(n) = 1 + T(n/2)\), with base case \(T(1) = 1\) (slide 6). Linear search does constant work and one call on one fewer item: \(T(n) = T(n-1) + 1\). The list summation on slide 11 makes two calls, each on half: \(T(n) = 2T(n/2) + 1\).

// slide 11: recursive list summation
private int sum_helper(int[] list, int low, int high){
  if (low == high){ return 0; }
  if (low == high-1){ return list[low]; }
  int middle = (high+low)/2;
  return sum_helper(list, low, middle) + sum_helper(list, middle, high);
}

Unroll it once (slide 7)

\(T(n) = 1 + T(n/2) = 1 + 1 + T(n/4) = 1 + 1 + 1 + T(n/8) = \cdots\). Substitute until you reach \(T(1)\). That takes \(\log_2 n\) halvings, so \(T(n) = \sum_{i=1}^{\log_2 n} 1 = \log_2 n\) plus the base case's 1, which is \(\Theta(\log n)\).

Quick check: in \(T(n) = a\cdot T(n/b) + f(n)\) form, what is \(a\) for sum_helper?

Quick check: which recurrence models linearSearch in the worst case?

Teaching notes
  • Ask for three numbers before writing anything: how many recursive calls (\(a\)), how the input shrinks (\(/b\) or \(-c\)), and the work outside the calls (\(f(n)\)). Section 3 drills exactly this.
  • "Chip and conquer" chips one item (or \(c\) items) off; "divide and conquer" divides by \(b\). The tree method handles both.
  • The slide's sum \(\sum_{i=1}^{\log_2 n} 1 = \log_2 n\) leaves out the base case's 1. Running the recurrence gives \(T(1024) = 11\), not 10. Both are \(\Theta(\log n)\): base cases never change the class.

Lecture 6 · slides 8, 10, 12–15 · Mon Oct 12

The tree method

Draw one box per stack frame (the slides' red boxes) and write the work done in that frame next to it (the blue numbers). Add across each level, then add the levels. Pick any of the lecture's recurrences below and change \(n\): the table sums each level exactly and checks the total against the recurrence itself.

Divide and conquer (slide 15): \(T(n) = aT(n/b) + f(n)\).

  • \(a\) is the branching factor: each box has \(a\) children.
  • A child's size is its parent's size divided by \(b\). Level \(i\) has \(a^i\) boxes of size \(n/b^i\).
  • Each box does \(f(\text{its size})\) work, so level \(i\) does \(a^i f(n/b^i)\).
  • The height is \(\log_b n\): how many times you divide by \(b\) to reach 1.

Chip and conquer (slide 14): \(T(n) = aT(n-b) + f(n)\).

  • Each box has \(a\) children.
  • A child's size is its parent's size minus \(b\). Level \(i\) has \(a^i\) boxes of size \(n - bi\).
  • Level \(i\) does \(a^i f(n - bi)\) work.
  • The height is \(n/b\): how many times you subtract \(b\) to reach 0.

Then write the series \(\sum_i (\text{work on level } i)\) from \(i = 0\) to the height, and solve it. Any base case is a constant, so stopping at a slightly larger size only changes constants.

List summation (slides 12–13). \(T(n) = 2T(n/2) + 1\): level \(i\) has \(2^i\) boxes doing 1 each, so

\[T(n) = \sum_{i=0}^{\log_2 n} 2^i = \frac{2^{1+\log_2 n} - 1}{2 - 1} = 2\cdot 2^{\log_2 n} - 1 = 2n - 1 \in \Theta(n).\]

The last step uses the finite geometric series from the Math Identities sheet (it's provided on exams).

Quick check: for \(T(n) = 2T(n/2) + 1\) with \(n = 16\), how many boxes are on the bottom level?

Quick check: same recurrence, \(T(1) = 1\), \(n = 16\). What is the total work \(T(16)\)?

Teaching notes
  • Have students fill in one row of the table by hand before using the widget: boxes on the level, size of each, work in each, product. The product is the only thing that goes into the sum.
  • Off-by-one on the number of levels is the usual slip. With base case \(n = 1\), sizes \(n, n/2, \dots, 1\) give \(\log_2 n + 1\) levels, which is why the sum runs from \(i = 0\) to \(\log_2 n\). It never changes the \(\Theta\).
  • Linear search's tree is a path of \(n\) boxes; binary search's is a path of \(\log_2 n + 1\). One child per box means no doubling.

Lecture 6 · slides 16–23 · Mon Oct 12

Solving the series

Slide 16 gives three more, each with base case \(T(1) = 1\). Try each one in the explorer on the previous page.

\(T(n) = 2T(n/2) + n\) (slide 17)

Level \(i\) has \(2^i\) boxes of size \(n/2^i\), each doing \(n/2^i\) work, so every level does \(2^i\cdot\frac{n}{2^i} = n\). There are \(\log_2 n\) levels above the leaves:

\[T(n) = \sum_{i=0}^{\log_2 n} n \in \Theta(n\log n).\]

\(T(n) = 2T(n/2) + n^2\) (slides 18–19)

A box of size \(n/2^i\) does \(\left(\frac{n}{2^i}\right)^2 = \frac{n^2}{4^i}\) work, and there are \(2^i\) of them, so level \(i\) does \(\frac{n^2}{2^i}\). The work shrinks as you go down:

\[T(n) = \sum_{i=0}^{\log_2 n} \frac{n^2}{2^i} = n^2\sum_{i=0}^{\log_2 n} \left(\tfrac12\right)^i \le n^2\cdot 2 \in \Theta(n^2),\]

using \(\sum_{i=0}^{\infty} x^i = \frac{1}{1-x}\) for \(|x| < 1\). The root's \(n^2\) is already a lower bound, so it's \(\Theta(n^2)\).

\(T(n) = 2T(n/8) + 1\) (slides 20–21)

Level \(i\) has \(2^i\) boxes doing 1 each. Dividing by 8 reaches 1 after \(\log_8 n\) levels:

\[T(n) = \sum_{i=0}^{\log_8 n} 2^i = \frac{2^{1+\log_8 n} - 1}{2-1} = 2\cdot 2^{\log_8 n} - 1 = 2n^{\log_8 2} - 1 \in \Theta(n^{1/3}),\]

using \(a^{\log_b c} = c^{\log_b a}\): \(2^{\log_8 n} = n^{\log_8 2} = n^{1/3}\).

What matters, recursively (slide 22)

For \(T(n) = aT(n/b) + f(n)\), the asymptotic answer depends on \(a\), \(b\) and the asymptotic behavior of \(f(n)\). It does not depend on the constants and non-dominant terms in \(f(n)\), or on the base case.

Lecture 6: practice

Six problems built from the lecture's own recurrences (slides 4–23). Every number was computed by evaluating the recurrence exactly (see checks/cse332/w03/verify.mjs). Formula boxes take expressions in \(n\) and \(i\), like 2^i or n^2/2^i.

1. Recursive binary search

Slide 6 models binarySearch by \(T(n) = 1 + T(n/2)\) with \(T(1) = 1\).

  1. Unroll: \(T(n) = 1 + T(n/2) = 2 + T(n/4) = \cdots\). How many 1s pile up before you reach \(T(1)\)?
  2. \(1024 = 2^{10}\). Ten halvings get you to \(T(1)\), and \(T(1)\) itself is 1.
  1. Each call makes one recursive call, so \(a = 1\).
  2. \(T(1024) = 1 + T(512) = 2 + T(256) = \dots = 10 + T(1) = 11\).
  3. In general \(T(n) = \log_2 n + 1\).
  4. \(a = 1\); \(T(1024) = 11\); \(\Theta(\log n)\).

2. The list-summation tree

Slide 12: \(T(n) = 2T(n/2) + 1\), \(T(1) = 1\). Level 0 is the root.

  1. Every box has 2 children. How many boxes does level 1 have? Level 2?
  2. For \(n = 16\) the levels have 1, 2, 4, 8 and 16 boxes, each doing 1.
  1. Level \(i\) has \(2^i\) boxes, each doing 1 unit of work.
  2. \(n = 16\): \(1 + 2 + 4 + 8 + 16 = 31\). The formula is \(2n - 1\).
  3. \(\sum_{i=0}^{\log_2 n} 2^i = 2n - 1 \in \Theta(n)\).
  4. \(2^i\); 31; \(\Theta(n)\).

3. \(T(n) = 2T(n/2) + n^2\)

Slides 18–19, with \(T(1) = 1\). Count level work above the leaves.

  1. A box on level \(i\) has size \(n/2^i\), so it does \((n/2^i)^2\). How many such boxes are there?
  2. For \(T(8)\), build up: \(T(2) = 2\cdot1 + 4\), then \(T(4)\), then \(T(8)\).
  1. Each box: \(\frac{n^2}{4^i}\). Boxes: \(2^i\). Level total: \(\frac{n^2}{2^i}\).
  2. \(T(2) = 2 + 4 = 6\), \(T(4) = 12 + 16 = 28\), \(T(8) = 56 + 64 = 120\). (Check: \(2n^2 - n = 128 - 8 = 120\).)
  3. \(n^2\sum_i (1/2)^i \le 2n^2\), and the root alone does \(n^2\).
  4. \(\frac{n^2}{2^i}\); 120; \(\Theta(n^2)\).

4. \(T(n) = 2T(n/8) + 1\)

Slides 20–21, with \(T(1) = 1\). Take \(n = 512\).

  1. Sizes go 512, 64, 8, 1. That's the number of levels.
  2. Level \(i\) has \(2^i\) boxes doing 1 each. And \(2^{\log_8 n} = n^{\log_8 2}\).
  1. 512, 64, 8, 1: four levels, \(i = 0\) to \(\log_8 512 = 3\).
  2. \(T(512) = 1 + 2 + 4 + 8 = 15 = 2\cdot 512^{1/3} - 1\).
  3. 4 levels; 15; \(\Theta(n^{1/3})\).

5. Recognize the common ones

From slide 23. Give the closed form of each.

  1. Draw two levels of each tree. Is the level work growing, flat or shrinking?
  2. \(O(n) + T(n/2)\): \(n + n/2 + n/4 + \cdots\). \(O(n) + T(n-1)\): \(n + (n-1) + \cdots + 1\).
  1. \(2T(n-1) + 1\): level \(i\) has \(2^i\) boxes, and there are \(n\) levels: \(\sum 2^i = 2^n - 1\).
  2. \(T(n-1) + n\): one box per level, sizes \(n, n-1, \dots, 1\): \(\frac{n(n+1)}{2}\).
  3. \(T(n/2) + n\): \(n(1 + \frac12 + \frac14 + \cdots) \le 2n\).
  4. \(2T(n/2) + n\): \(n\) per level, \(\log_2 n\) levels.
  5. \(\Theta(2^n)\); \(\Theta(n^2)\); \(\Theta(n)\); \(\Theta(n\log n)\).

6. What changes the answer?

Start from \(T(n) = 2T(n/2) + n\), \(T(1) = 1\), which is \(\Theta(n\log n)\). Does each change give a different \(\Theta\) class?

  1. Slide 22 lists what matters: \(a\), \(b\) and the asymptotic behavior of \(f\).
  2. For the last two, find the level-\(i\) work: \(4^i\cdot\frac{n}{2^i}\) and \(2^i\cdot\frac{n}{4^i}\).
  1. The base case and the constants in \(f\) only scale things: still \(\Theta(n\log n)\).
  2. \(4T(n/2) + n\): level \(i\) does \(2^i n\), growing, so the leaves win: \(\Theta(n^2)\).
  3. \(2T(n/4) + n\): level \(i\) does \(\frac{n}{2^i}\), shrinking, so the root wins: \(\Theta(n)\).
  4. no; no; yes; yes.

Check your understanding: recurrences

Ten questions on Lecture 6. Answer without looking back. The score counts first tries.

  1. Which recurrence is "chip and conquer"?

  2. \(T(n) = T(n/2) + 1\). Give its \(\Theta\) class.

    One box per level, \(\log_2 n + 1\) levels, 1 each: \(\Theta(\log n)\).

  3. \(T(n) = 2T(n/2) + n\). Give its \(\Theta\) class.

    Every level does \(n\) work, and there are about \(\log_2 n\) levels.

  4. \(T(n) = 2T(n/2) + n\), \(T(1) = 1\). What is \(T(8)\)?

    Levels: 8, 8, 8, then 8 leaves doing 1 each: \(8 + 8 + 8 + 8 = 32\). Or build up: \(T(2) = 4\), \(T(4) = 12\), \(T(8) = 32\).

  5. \(T(n) = T(n-1) + n\). Give its \(\Theta\) class.

    \(n + (n-1) + \cdots + 1 = \frac{n(n+1)}{2} \in \Theta(n^2)\).

  6. How tall is the tree for \(T(n) = aT(n/b) + f(n)\)?

  7. \(T(n) = 2T(n/2) + n^2\). Give its \(\Theta\) class.

    Level \(i\) does \(n^2/2^i\): a geometric series with ratio \(\frac12\), at most \(2n^2\). The root dominates.

  8. Which of these never changes the \(\Theta\) class of \(T(n) = aT(n/b) + f(n)\)?

  9. In the tree for \(T(n) = 3T(n/2) + n\), how many boxes are on level 3 (the root is level 0)?

    Each box has 3 children: \(3^3 = 27\).

  10. \(T(n) = 2T(n-1) + 1\). Give its \(\Theta\) class.

    \(n\) levels, level \(i\) has \(2^i\) boxes: \(\sum_{i=0}^{n-1} 2^i = 2^n - 1\).

The dictionary ADT

Dictionary (Map) ADT. A set of key + value pairs. Keys are unique (always) and comparable (for many implementations).

insert(key, value) adds the pair; if the key already has a value, it overwrites it, so keys can't repeat. find(key) returns the key's value. delete(key) removes the key and its value.

Uses (slide 4): router tables, page tables, compilers' symbol tables, databases, inverted indexes, genome maps. Any time you store information by a key and want it back fast.

Insert into an unsorted array is \(\Theta(n)\) here, not \(\Theta(1)\): keys are unique, so insert has to look for the key first to overwrite it.

Lazy deletion (slide 7)

A general trick to make delete as fast as find: don't remove the item, just mark it deleted. No shifting. It's simpler, removals can happen later in batches, and a re-added key is just unmarked. The costs: a flag per item, space wasted on deleted items, and find becomes \(O(\log m)\) where \(m \ge n\) counts the deleted items too.

The next lectures look at two better dictionaries: AVL trees (BSTs with guaranteed balance) and hash tables (not tree-like at all).

Trees, traversals, BSTs

Traversal: an algorithm that visits every node (slide 9). For the tree with root D, children U and B, and U's children S and 2:

  • Pre-order (root, left, right): D U S 2 B
  • In-order (left, root, right): S U 2 D B
  • Post-order (left, right, root): S 2 U B D
// slide 11: the answer to "name that traversal"
postOrder(root) {
  if (root.left != Null) postOrder(root.left);
  if (root.right != Null) postOrder(root.right);
  process(root);
}
// preOrder: process(root) first; inOrder: in the middle

Binary search tree (slide 12). A binary tree (each node has at most 2 children) with the order property: every key in the left subtree is smaller than the node's key, and every key in the right subtree is larger. So keys can't repeat.

Are these BSTs? (slides 13–14)

The third tree is the trap: 8 is bigger than its parent 3, which is fine locally, but it sits in the left subtree of 7, where every key must be smaller than 7.

max # of leaves\(2^h\)

So with \(n\) nodes we can't do better than \(O(\log n)\) height, and we want to avoid \(O(n)\) height. BSTs use nodes and references rather than an array (slide 17): a BST can have gaps, and an array with gaps can need about \(2^n\) slots.

Find, insert, delete

// slide 19: find (iterative)
find(key, root) {
  while (root != Null && key != root.key) {
    if (key < root.key) root = root.left;
    else if (key > root.key) root = root.right;
  }
  if (root == Null) return Null;
  return root.value;
}
// slide 20: insert (recursive)
insertHelper(key, value, root) {
  if (root == null)
    return new Node(key, value);
  if (root.key < key)
    root.right = insertHelper(key, value, root.right);
  else
    root.left = insertHelper(key, value, root.left);
  return root;
}

Insert happens only at the leaves. (The iterative version on slide 21 overwrites the value when the key is already there.)

Delete: three cases (slides 23–26)

  • 0 children (a leaf, e.g. delete 5): the parent points to null instead.
  • 1 child (e.g. delete 1): replace the node with its child.
  • 2 children (e.g. delete 3): replace it with the largest key to its left, or else the smallest key to its right. The recursive version on slide 26 uses removeMax(root.left), the largest to the left.

The max of a BST is its right-most node; the min is its left-most node (slide 24).

Worst case (slides 27–29)

Find, insert and delete each take time proportional to the tree's height. The maximum height of a BST with \(n\) nodes is \(n - 1\): insert keys in sorted order and you get a chain. So the worst case is \(\Theta(n)\). To do better, add shape rules that keep the tree short. That's the AVL tree, on Friday.

What balanced means

A node's height is the number of edges on the longest path from it down to a leaf. A leaf has height 0, and an empty subtree counts as \(-1\). So a node's height is \(1 + \max(\text{left height}, \text{right height})\). Each node stores its own height, next to its key, value and two children.

A node's balance is its left subtree's height minus its right subtree's height.

AVL tree. A BST where every node's balance is \(-1\), \(0\) or \(+1\): at every node, the two subtrees' heights differ by at most 1. A node whose subtrees differ by more is a problem node.

Purple: each node's height. Under each node: its balance.

In the right tree, 3 has no left child (height \(-1\)) and its right child 6 has height 1: \(-1 - 1 = -2\). The root is fine (\(2 - 1 = +1\)). One problem node anywhere breaks the rule, so check every node, not just the root.

Why this rule and not a simpler one?
RuleThe issue
The root's two subtrees have the same number of nodesToo weak: each side can still be a long chain.
The root's two subtrees have the same heightToo weak: the same chains, just equally long.
Every node's two subtrees have the same number of nodesToo strong: some sizes are impossible, like a tree of 2 nodes.
Every node's two subtrees have the same heightToo strong: again, no tree of 2 nodes.

AVL allows a difference of 1 at every node. That's strong enough to keep the tree short and loose enough to work for any number of nodes.

Insert and rotate

Insert starts as a plain BST insert: the new key becomes a leaf. Only the nodes on the path from that leaf up to the root can change height, because nothing else moved. So walk back up that path, update each height, and stop at the first node whose two children differ by 2. Fix it with a rotation. Step through the lecture's example, inserting −1:

The rule. After the rotation, the fixed subtree is exactly as tall as it was before the insert, so nothing above it changes. One fix per insert, at the first unbalanced node on the way up: the deepest one.

The rule. \(M(h)\) grows like the Fibonacci numbers: each one is a bit more than 1.6 times the one before. So an AVL tree of height \(h\) has at least \(1.6^h\) nodes, and with \(n\) nodes its height is at most about \(\log_{1.6} n\). Find, insert and delete are all \(\Theta(\log n)\) in the worst case.

With a million keys, a plain BST can reach height 999,999. An AVL tree stays at height 27 or less. The shortest possible tree, a complete one, has height 19.

The proof, with the Fibonacci numbers

Fibonacci: \(F(0) = 0\), \(F(1) = 1\), \(F(h) = F(h-1) + F(h-2)\). \(M\) starts bigger and adds an extra 1 at each step, so \(M(h) > F(h)\). For large \(h\), \(F(h)\) grows like \(\phi^h\), where \(\phi \approx 1.618\) is the golden ratio.

In fact \(M(h) \ge \phi^h\) for every \(h\): it holds for \(h = 0\) and \(h = 1\), and \(\phi^{h-1} + \phi^{h-2} = \phi^h\), so it carries up the recurrence. A tree with \(n\) nodes and height \(h\) has \(n \ge M(h) \ge \phi^h\), so \(h \le \log_\phi n\): the operations are \(O(\log n)\).

The other way: a tree of height \(h\) has at most \(2^{h+1} - 1\) nodes, so even the best tree has height at least \(\log_2(n+1) - 1\). The operations are \(\Omega(\log n)\) too, so \(\Theta(\log n)\).

Recurrences

Divide and conquer \(T(n) = aT(n/b) + f(n)\); chip and conquer \(T(n) = aT(n-b) + f(n)\). \(a\) = calls per call, \(b\) = how the input shrinks, \(f\) = work outside the calls.

Matters: \(a\), \(b\), the class of \(f\). Doesn't: constants in \(f\), the base case.

Tree method

Level \(i\): \(a^i\) boxes of size \(n/b^i\) (or \(n - bi\)), level work \(a^i f(n/b^i)\). Height \(\log_b n\) (or \(n/b\)). Sum the levels.

Level work grows: leaves win. Flat: work × levels. Shrinks: root wins.

Series

\(\sum_{i=0}^{k} x^i = \frac{x^{k+1}-1}{x-1}\); \(\sum_{i=0}^{\infty} x^i = \frac1{1-x}\) for \(|x|<1\).

\(a^{\log_b c} = c^{\log_b a}\), e.g. \(2^{\log_8 n} = n^{1/3}\), \(3^{\log_2 n} = n^{\log_2 3}\).

Dictionaries and BSTs

insert(k, v) overwrites an existing key; find(k); delete(k). BST: left subtree < node < right subtree, for whole subtrees.

Pre-order: root, L, R. In-order: L, root, R (sorted). Post-order: L, R, root.

Delete: leaf → null; one child → the child; two children → max of the left (or min of the right).

Tree numbers (height \(h\), edges)

Leaves: at most \(2^h\), at least 1. Nodes: at most \(2^{h+1}-1\), at least \(h+1\). Empty tree: height −1. BST find/insert/delete: \(\Theta(\text{height})\), worst \(\Theta(n)\).

AVL insert

BST insert, update heights up the path, rotate at the deepest unbalanced node:

LL → right at it. RR → left at it. LR → left at the left child, then right. RL → right at the right child, then left. One case and you're done.

AVL height

\(M(h) = M(h-1) + M(h-2) + 1\): 1, 2, 4, 7, 12, 20, 33, 54, 88. \(M(h) > \phi^h\), so \(h \le \log_\phi n\): every operation \(\Theta(\log n)\).
