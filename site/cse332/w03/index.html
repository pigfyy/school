Lecture 6 · Mon Oct 12

Same tree, three answers

\(T(n) = 2T(n/2) + 1\), \(2T(n/2) + n\) and \(2T(n/2) + n^2\) all draw the same binary tree of calls. Why are they \(\Theta(n)\), \(\Theta(n\log n)\) and \(\Theta(n^2)\)?

Look at the bars. With \(+1\) the work doubles on every level, so the leaves dominate and the total is about \(2n\). With \(+n\) every level does exactly \(n\) work, and there are \(\log_2 n + 1\) levels. With \(+n^2\) the work halves on every level, so the root dominates and the total is under \(2n^2\). That's the tree method: draw the calls, add up each level, then add up the levels.

Writing a recurrence

\(T(n)\) is the time the code takes on an input of size \(n\). A recursive call on a smaller input costs \(T(\text{its size})\), so \(T\) appears on both sides. Fill in three blanks:

The template

\(T(n) =\) \(a\) \(\cdot\; T\big(\)size\(\big) \;+\) \(f(n)\), with a constant base case.

  • \(a\): how many recursive calls one call makes.
  • size: the input of each call. \(\frac{n}{b}\) is divide and conquer. \(n - b\) is chip and conquer.
  • \(f(n)\): the work one call does outside its recursive calls.

Worked example

The lecture's recursive list sum. sum_helper adds up list[low] to list[high-1], so its input size is \(n = \) high - low. Write its recurrence.

1private int sum_helper(int[] list, int low, int high){2  if (low == high){ return 0; }3  if (low == high-1){ return list[low]; }4  int middle = (high+low)/2;5  return sum_helper(list, low, middle) + sum_helper(list, middle, high);6}
  1. base case\(T(1) = 1\)lines 2–3: 0 or 1 items returns at once, a constant
  2. \(a\)\(2\)line 5 makes two calls
  3. size\(\frac{n}{2}\)low to middle and middle to high: each is half
  4. \(f(n)\)\(1\)line 4 and the + on line 5: a constant, written 1

  5. Fill in the template

    \(T(n) =\) \(2\) \(\cdot\; T\big(\)\(\frac n2\)\(\big) \;+\) \(1\), with \(T(1) = 1\).

    Divide and conquer, with \(a = 2\) and \(b = 2\).

The rule. Count the calls that actually run (\(a\)), how big each one is (\(\frac nb\) or \(n - b\)), and the work around them (\(f(n)\)). Any constant amount of work is written as 1. The base case is a constant too.

The rule. For \(T(n) = aT(n/b) + f(n)\), level \(i\) has \(a^i\) calls, each of size \(\frac{n}{b^i}\). Work for the level is calls × \(f(\text{size})\). The tree ends at the base case, where \(\frac{n}{b^i} = 1\): level \(i = \log_b n\). That makes \(\log_b n + 1\) levels.

Chip and conquer, \(T(n) = aT(n - b) + f(n)\), works the same way, but the size on level \(i\) is \(n - bi\), so the tree is about \(\frac nb\) levels tall.

Solving the series

The lecture's three recurrences all draw the same tree: 2 calls, each on half. Only \(f(n)\) changes. Here is the work for each level at \(n = 16\), with \(T(1) = 1\).

The rule. Write the work for level \(i\) and see how it changes from one level to the next.

  • Grows by a constant factor: the bottom level sets the answer. Count the leaves: \(a^{\log_b n}\) of them.
  • Same on every level: work per level × number of levels.
  • Shrinks by a constant factor: the root sets the answer, \(f(n)\).

Why: a sum that doubles at each step is less than 2 × its last term (\(1 + 2 + 4 + 8 = 15 < 16\)). A sum that halves at each step is less than 2 × its first term.

The lecture's exact sums

The Math Identities sheet (given on exams) has the two series the lecture uses: \(\sum_{i=0}^{k} x^i = \frac{x^{k+1} - 1}{x - 1}\), and \(\sum_{i=0}^{\infty} x^i = \frac{1}{1-x}\) when \(|x| < 1\).

\(2T(n/2) + 1\): \(\sum_{i=0}^{\log_2 n} 2^i = \frac{2^{1+\log_2 n} - 1}{2 - 1} = 2n - 1\).

\(2T(n/2) + n^2\): \(\sum_{i=0}^{\log_2 n} \frac{n^2}{2^i} \le n^2 \sum_{i=0}^{\infty} \left(\tfrac12\right)^i = 2n^2\). The root alone is \(n^2\), so it's \(\Theta(n^2)\).

\(2T(n/8) + 1\): level \(i\) does \(2^i\), and the last level is \(\log_8 n\). \(\sum_{i=0}^{\log_8 n} 2^i = 2\cdot 2^{\log_8 n} - 1 = 2n^{1/3} - 1\), using \(a^{\log_b c} = c^{\log_b a}\). So \(\Theta(n^{1/3})\): the leaves win, and there are only \(n^{1/3}\) of them.

What changes the answer

For \(T(n) = aT(n/b) + f(n)\), these matter: the value of \(a\), the value of \(b\), and the growth of \(f(n)\). These never do: constants and smaller terms in \(f(n)\), and the base case.

The dictionary ADT

A dictionary (also called a map) stores key + value pairs, like a phone book: look up a name (the key), get back a number (the value). Keys are unique. Most implementations also need keys to be comparable: for any two keys, you can tell which is smaller.

operationdoes
insert(key, value)add the pair; if the key is already there, overwrite its value
find(key)return the key's value
delete(key)remove the key and its value

Worst cases, with \(n\) keys stored.

Insert is \(\Theta(n)\) even unsorted: keys are unique, so insert first has to look for the key, in case it must overwrite.

Sorted array: find is binary search, but insert and delete shift items over to make or close a gap.

Linked list: no binary search, because you can't jump to the middle. Heap: good at the minimum only; any other key could be anywhere.

The rule. Every list-like choice is \(\Theta(n)\) for something. A binary search tree aims to make all three \(\Theta(\log n)\).

Lazy deletion

Instead of removing an item, mark it deleted. Nothing shifts, so delete costs just a find. Removals can be done later in a batch, and a key that's re-added soon is just unmarked. The costs: an extra flag per item, space wasted on deleted items, and find takes \(O(\log m)\) in a sorted array, where \(m \ge n\) counts the deleted items too.

Quick check: a dictionary of \(n\) keys is loaded once, then only searched: millions of find calls, no more inserts or deletes. Which naïve choice is best?

Trees and traversals

A binary tree: each node has at most 2 children, a left and a right.

  • Root: the top node, D.
  • Leaf: a node with no children: S, 2 and B.
  • Subtree: a node and everything below it. U's subtree is U, S, 2.
  • Height: the number of edges on the longest path from the root down to a leaf. This tree has height 2. A single node has height 0.

Traversals

A traversal visits every node once. The three standard ones make the same recursive walk. They differ only in when they process (write down) the node:

pre-orderroot, then left subtree, then right subtree
in-orderleft subtree, then root, then right subtree
post-orderleft subtree, then right subtree, then root

The rule. Pre-order writes a node on the way down, before its subtrees. In-order writes it between its left and right subtrees. Post-order writes it on the way back up, after both. A leaf has no subtrees, so all three write it at the same moment.

The BST property

Binary search tree (BST). A binary tree where, at every node, all keys in its left subtree are smaller than its key, and all keys in its right subtree are larger. So keys can't repeat.

This is the lecture's BST. Read the keys left to right, which is the in-order traversal, and they come out sorted: 0 1 2 3 6 7 8 10 16. Every BST does this, so it's a quick test.

Is this a BST?

  1. 8 is the right child of 3, and \(8 > 3\). Fine so far.
  2. 8 is also in 7's left subtree, where every key must be smaller than 7. But \(8 > 7\). Not a BST.
  3. In-order reads 0 1 3 8 7 10 16. Not sorted: same verdict.

Common mistake. Checking only each parent and its children. Compare a key with every node above it, or just check that in-order is sorted.

Find and insert

To find a key, start at the root and compare. Smaller: go left. Larger: go right. Equal: found. If you step onto an empty child, the key isn't in the tree. Insert runs the same loop, then puts the new key in the empty spot where find fell off.

The worst case

Find, insert and delete each walk one path down from the root, so in the worst case their time is the tree's height. How tall can a BST with \(n\) nodes get? Insert 1, 2, 3, 4, 5 in that order. Each key is larger than every key before it, so each one goes right of the last:

A chain. Its height is 4, which is \(n - 1\), and find(5) compares with all 5 keys. So in the worst case find, insert and delete are all \(\Theta(n)\): no better than a list.

How short can it be?

The fewest leaves is always 1, a chain. A full tree packs 15 nodes into height 3, so \(n\) nodes need height at least about \(\log_2 n\). A chain stretches them to height \(n - 1\). Every BST is somewhere in between.

The rule. BST operations cost \(\Theta(\text{height})\). The height can be anywhere from about \(\log_2 n\) to \(n - 1\), so the worst case is \(\Theta(n)\). Random insert orders usually give short trees (expected \(\Theta(\log n)\)), but nothing guarantees it. AVL trees (Lecture 8) add a shape rule that keeps the height \(\Theta(\log n)\) always.

The point. Find, insert and delete in a BST cost the tree's height, and a plain BST can grow into a chain of height \(n - 1\). An AVL tree is a BST with one balance rule, restored by rotations after each insert, so its height stays \(\Theta(\log n)\).

What balanced means

A node's height is the number of edges on the longest path from it down to a leaf. A leaf has height 0, and an empty subtree counts as \(-1\). So a node's height is \(1 + \max(\text{left height}, \text{right height})\). Each node stores its own height, next to its key, value and two children.

A node's balance is its left subtree's height minus its right subtree's height.

AVL tree. A BST where every node's balance is \(-1\), \(0\) or \(+1\): at every node, the two subtrees' heights differ by at most 1. A node whose subtrees differ by more is a problem node.

Purple: each node's height. Under each node: its balance.

In the right tree, 3 has no left child (height \(-1\)) and its right child 6 has height 1: \(-1 - 1 = -2\). The root is fine (\(2 - 1 = +1\)). One problem node anywhere breaks the rule, so check every node, not just the root.

Why this rule and not a simpler one?
RuleThe issue
The root's two subtrees have the same number of nodesToo weak: each side can still be a long chain.
The root's two subtrees have the same heightToo weak: the same chains, just equally long.
Every node's two subtrees have the same number of nodesToo strong: some sizes are impossible, like a tree of 2 nodes.
Every node's two subtrees have the same heightToo strong: again, no tree of 2 nodes.

AVL allows a difference of 1 at every node. That's strong enough to keep the tree short and loose enough to work for any number of nodes.

Insert and rotate

Insert starts as a plain BST insert: the new key becomes a leaf. Only the nodes on the path from that leaf up to the root can change height, because nothing else moved. So walk back up that path, update each height, and stop at the first node whose two children differ by 2. Fix it with a rotation. Step through the lecture's example, inserting −1:

new keybeing checkedunbalancedmoved upmoved across

Right rotation at \(a\). Its left child \(b\) moves up into \(a\)'s place, and \(a\) becomes \(b\)'s right child. \(b\)'s old right subtree moves across to be \(a\)'s left subtree. Then recompute \(a\)'s height, then \(b\)'s. The keys keep their left-to-right order, so it's still a BST.

Node b = a.left
a.left = b.right
b.right = a
return b

Left rotation is the mirror image: the right child moves up. Either way, three references change, so a rotation is \(\Theta(1)\).

The rule. After the rotation, the fixed subtree is exactly as tall as it was before the insert, so nothing above it changes. One fix per insert, at the first unbalanced node on the way up: the deepest one.

The lecture's insert code

The walk back up is the recursion returning: each call checks its own node after the call below it has finished.

insertHelper(key, value, root) {
  if (root == null)
    return new Node(key, value);
  if (root.key < key)
    root.right = insertHelper(key, value, root.right);
  else
    root.left = insertHelper(key, value, root.left);
  if (isUnbalanced(root))
    root = rotate(root);
  return root;
}

Why the height is \(\Theta(\log n)\)

Every AVL operation walks one path, so it costs the tree's height. How tall can an AVL tree with \(n\) nodes get? Turn it around: let \(M(h)\) be the fewest nodes an AVL tree of height \(h\) can have. Here are the smallest ones:

The recurrence

A tree of height \(h\) needs one subtree of height \(h-1\). The balance rule lets the other be as short as \(h-2\), and no shorter. Make both as small as possible and add the root:

\[M(h) = M(h-1) + M(h-2) + 1, \qquad M(0) = 1,\ M(1) = 2\]

  1. \(M(2)\)\(= M(1) + M(0) + 1 = 2 + 1 + 1 = 4\)the \(h = 2\) tree above
  2. \(M(3)\)\(= M(2) + M(1) + 1 = 4 + 2 + 1 = 7\)the \(h = 3\) tree
  3. \(M(4)\)\(= 7 + 4 + 1 = 12\)
\(h\)0123456
\(M(h)\)1247122033

The rule. \(M(h)\) grows like the Fibonacci numbers: each one is a bit more than 1.6 times the one before. So an AVL tree of height \(h\) has at least \(1.6^h\) nodes, and with \(n\) nodes its height is at most about \(\log_{1.6} n\). Find, insert and delete are all \(\Theta(\log n)\) in the worst case.

With a million keys, a plain BST can reach height 999,999. An AVL tree stays at height 27 or less. The shortest possible tree, a complete one, has height 19.

The proof, with the Fibonacci numbers

Fibonacci: \(F(0) = 0\), \(F(1) = 1\), \(F(h) = F(h-1) + F(h-2)\). \(M\) starts bigger and adds an extra 1 at each step, so \(M(h) > F(h)\). For large \(h\), \(F(h)\) grows like \(\phi^h\), where \(\phi \approx 1.618\) is the golden ratio.

In fact \(M(h) \ge \phi^h\) for every \(h\): it holds for \(h = 0\) and \(h = 1\), and \(\phi^{h-1} + \phi^{h-2} = \phi^h\), so it carries up the recurrence. A tree with \(n\) nodes and height \(h\) has \(n \ge M(h) \ge \phi^h\), so \(h \le \log_\phi n\): the operations are \(O(\log n)\).

The other way: a tree of height \(h\) has at most \(2^{h+1} - 1\) nodes, so even the best tree has height at least \(\log_2(n+1) - 1\). The operations are \(\Omega(\log n)\) too, so \(\Theta(\log n)\).

6. How tall can it get?

\(M(h)\) is the fewest nodes an AVL tree of height \(h\) can have: \(M(h) = M(h-1) + M(h-2) + 1\), with \(M(5) = 20\), \(M(6) = 33\) and \(M(7) = 54\). Height counts edges, so a single node has height 0.

Recurrences

Divide and conquer \(T(n) = aT(n/b) + f(n)\); chip and conquer \(T(n) = aT(n-b) + f(n)\). \(a\) = calls per call, \(b\) = how the input shrinks, \(f\) = work outside the calls.

Matters: \(a\), \(b\), the class of \(f\). Doesn't: constants in \(f\), the base case.

Tree method

Level \(i\): \(a^i\) boxes of size \(n/b^i\) (or \(n - bi\)), level work \(a^i f(n/b^i)\). Height \(\log_b n\) (or \(n/b\)). Sum the levels.

Level work grows: leaves win. Flat: work × levels. Shrinks: root wins.

Series

\(\sum_{i=0}^{k} x^i = \frac{x^{k+1}-1}{x-1}\); \(\sum_{i=0}^{\infty} x^i = \frac1{1-x}\) for \(|x|<1\).

\(a^{\log_b c} = c^{\log_b a}\), e.g. \(2^{\log_8 n} = n^{1/3}\), \(3^{\log_2 n} = n^{\log_2 3}\).

Dictionaries and BSTs

insert(k, v) overwrites an existing key; find(k); delete(k). BST: left subtree < node < right subtree, for whole subtrees.

Pre-order: root, L, R. In-order: L, root, R (sorted). Post-order: L, R, root.

Delete: leaf → null; one child → the child; two children → max of the left (or min of the right).

Tree numbers (height \(h\), edges)

Leaves: at most \(2^h\), at least 1. Nodes: at most \(2^{h+1}-1\), at least \(h+1\). Empty tree: height −1. BST find/insert/delete: \(\Theta(\text{height})\), worst \(\Theta(n)\).

AVL insert

BST insert, update heights up the path, rotate at the deepest unbalanced node:

LL → right at it. RR → left at it. LR → left at the left child, then right. RL → right at the right child, then left. One case and you're done.

AVL height

\(M(h) = M(h-1) + M(h-2) + 1\): 1, 2, 4, 7, 12, 20, 33, 54, 88. \(M(h) > \phi^h\), so \(h \le \log_\phi n\): every operation \(\Theta(\log n)\).
