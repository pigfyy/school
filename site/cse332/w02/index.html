Who wins eventually?

Lecture 3 claims \(n^{50} \in O(1.1^n)\). At \(n = 100\), \(n^{50}\) has 101 digits and \(1.1^{n}\) is about 13,781. So is the claim wrong?

\(n^{50}\)…
vs
\(1.1^{n}\)…

Compared exactly with big integers: \(n^{50} \le 1.1^n \iff n^{50}\cdot 10^n \le 11^n\). The chart's height is the number of digits, so both curves fit on one axis.

The claim is right. \(1.1^n\) loses for a long time, but from \(n = 4{,}402\) on it stays ahead forever. The exact flip happens between 4,401 and 4,402. Big-O doesn't care about the first 4,401 inputs. It asks what happens for all large enough \(n\), and it makes "large enough" precise with two numbers, \(c\) and \(n_0\). That's Lecture 3. Lectures 4 and 5 then use it: a new ADT, the priority queue, and a data structure, the binary heap, that makes both of its operations \(\Theta(\log n)\).

Why binary search is \(\log n\)

Binary search checks the middle of a sorted list, then throws away the half that can't hold the target. Press Step.

Each loop halves what's left: \(16 \to 8 \to 4 \to 2 \to 1\). That's 4 halvings, because \(2^4 = 16\), plus one loop for the last item.

items \(n\)161,024a million
binary search51120
one by one161,024a million

The rule. Halving each loop takes about \(\log_2 n\) loops (worst case). Doubling the list adds just one loop.

The lecture's code 
public static boolean binary_contains(
        List<Integer> a, int k){
    int start = 0;          // k can only be in [start, end)
    int end = a.size();
    while(start < end){     // stop when nothing is left
        int mid = start + (end-start)/2;
        if(a.get(mid) == k)
               return true;
        else if(a.get(mid) < k)
               start = mid+1; // drop mid and the left
        else
               end = mid;     // drop mid and the right
    }
    return false;
}

Quick check: the list doubles in size, from \(n\) to \(2n\). How many more loops can binary search take in the worst case?

Buckets: the bigger one loses

Worked example

Algorithm A takes \(10n\) steps. Algorithm B takes \(n^2\). Which is faster?

\(n\)151020100
A: \(10n\)10501002001,000
B: \(n^2\)12510040010,000

B is faster at first. From \(n = 10\) on, A is never slower, and the gap keeps growing.

A = 10nB = n²

A bucket is the fastest-growing term, with its constant dropped. \(10n\) is in bucket \(n\), and \(n^2\) is in bucket \(n^2\). For big enough \(n\), the smaller bucket always wins, whatever the constants are.

Find the bucket

stepsbucket
\(3n + 5\)\(n\)
\(n^2 + 100n\)\(n^2\)
\(4\log n + 7\)\(\log n\)
\(2^n + n^3\)\(2^n\)

Slowest to fastest: \(1 < \log n < n < n\log n < n^2 < n^3 < 2^n\).

Watch out

  • Exponents and exponential bases stay: \(n^3\) isn't bucket \(n^2\), and \(3^n\) isn't bucket \(2^n\).
  • The log's base doesn't matter (\(\log_5 n\) is just \(\log_2 n \div 2.32\)), so write \(\log n\).

Quick check: which two are in the same bucket? \(D = 5n^2 + n\), \(E = 1000n + 7\), \(F = \frac{n^2}{2}\).

\(O\), \(\Omega\), \(\Theta\)

Each one compares a step count \(f\) to a simple function \(g\), like \(n\). Here \(f(n) = 2n + 10\) and \(g(n) = n\).

ceiling: 3nf = 2n + 10floor: 2n
in the picturelike
\(f \in O(n)\)\(f\) stays under a ceiling, \(3n\)\(\le\)
\(f \in \Omega(n)\)\(f\) stays over a floor, \(2n\)\(\ge\)
\(f \in \Theta(n)\)both: stuck between them\(=\)

You choose two things. The constant \(c\) in front of \(g\) (3 for the ceiling, 2 for the floor), and where it has to start holding, \(n_0\) (here 10). Before \(n_0\), anything goes. That's how constants and small \(n\) get ignored.

Worked example

Which claims about \(f(n) = 2n + 10\) are true?

  1. \(O(n^2)\)✓\(n^2\) is an even higher ceiling: true, just loose
  2. \(O(n)\)✓ceiling \(3n\), from the picture
  3. \(O(\log n)\)✗\(f\) breaks through any \(c\log n\)
  4. \(\Omega(n)\)✓floor \(2n\), from the picture
  5. \(\Omega(n^2)\)✗\(n^2\) climbs past \(f\), so it can't be a floor
  6. \(\Theta(n)\)✓both \(O(n)\) and \(\Omega(n)\)

  7. The rule. Compare buckets. \(O\): same bucket or a bigger one. \(\Omega\): same or smaller. \(\Theta\): same. When you know the bucket, say \(\Theta\).

Quick check: a paper says its algorithm's worst case is \(O(n^2)\). What can you conclude?

Quick check: you know \(f \in O(n^3)\) and \(f \in \Omega(n^3)\). What else is true?

Proving a bound

Every \(O\) proof has the same shape. You fill in two numbers, then show one inequality.

The template

Let \(c =\) ? and \(n_0 =\) ?.

Show: for every \(n \ge n_0\), \(f(n) \le c\cdot g(n)\).

algebra, one line at a time, until it's obviously true

This holds for every \(n \ge n_0\).

Worked example

Prove \(2n + 10 \in O(n)\).

  1. pick \(c\)\(c = 3\)just above the 2 in \(2n\)
  2. find \(n_0\)\(2n + 10 \le 3n\)when is this true?
  3. \(10 \le n\)take \(2n\) off both sides, so \(n_0 = 10\)

  4. Fill in the template

    Let \(c =\) \(3\) and \(n_0 =\) \(10\).

    Show: for every \(n \ge 10\), \(2n + 10 \le 3n\).

    \[\begin{aligned} &2n + 10 \le 3n\\ \equiv\ &10 \le n\end{aligned}\]

    This holds for every \(n \ge 10\).

See it

Red dots are where \(2n + 10\) is over \(3n\). Move \(n_0\) to 10 and they drop out.

\(\Omega\): same template, flip to \(\ge\)

Prove \(2n + 10 \in \Omega(n)\)

Let \(c =\) \(2\) and \(n_0 =\) \(1\).

Show: for every \(n \ge 1\), \(2n + 10 \ge 2n\).

\[\begin{aligned} &2n + 10 \ge 2n\\ \equiv\ &10 \ge 0\end{aligned}\]

This holds for every \(n \ge 1\).

Both proofs together give \(2n + 10 \in \Theta(n)\).

Not a proof

  • Checking a few values of \(n\). Argue for any \(n \ge n_0\).
  • A \(c\) that depends on \(n\), like "pick \(c = n\)". \(c\) is one fixed number.

Quick check: proving \(5n^2 + 30n \in O(n^2)\), you try \(c = 5\) and get \(30n \le 0\), false for every \(n \ge 1\). What next?

Quick check: a "proof" of \(2n + 10 \in O(n)\) says: "Let \(c = 3\), \(n_0 = 10\). At \(n = 10\): \(30 \le 30\). At \(n = 11\): \(32 \le 33\). At \(n = 12\): \(34 \le 36\). So it holds." What's wrong?

Case vs. bound

Two separate questions. The case (best or worst) picks which inputs you count, which gives one step count. The bound (\(O\), \(\Omega\), \(\Theta\)) says what you know about that count.

Worked example

Linear search checks items left to right until it finds \(k\). On \(n\) items:

whenstepstight
worst\(k\) missing\(n\)\(\Theta(n)\)
best\(k\) first\(1\)\(\Theta(1)\)
  1. worst, \(\Omega(n)\)✓even the worst case takes at least about \(n\)
  2. best, \(O(n)\)✓the best case takes at most \(n\): true, loose
  3. best, \(\Omega(n)\)✗the best case is 1 step

  4. The rule. Any bound goes with any case.

A common mix-up. \(O\) doesn't mean worst case, and \(\Omega\) doesn't mean best case. \(O\) is "at most" and \(\Omega\) is "at least", about whichever case you picked.

Quick check: "Every sorting algorithm takes at least \(n\log n\) time in the worst case." Which pair describes this claim?

Quick check: an algorithm's worst case is \(O(n)\). What does that tell you about its best case?

Binary search and logs

Lesson: Why binary search is log n

1. Halving the gap

This practices the lecture's argument for why binary search takes about \(\log_2 n\) loop iterations. Here is the lecture's binary search on a sorted list a of \(n\) items:

public static boolean binary_contains(
        List<Integer> a, int k){
    int start = 0;
    int end = a.size();
    while(start < end){
        int mid = start + (end-start)/2;
        if(a.get(mid) == k)
               return true;
        else if(a.get(mid) < k)
               start = mid+1;
        else
               end = mid;
    }
    return false;
}

The gap is end - start, the number of items that could still hold \(k\). It starts at \(n\), and each iteration of the while loop roughly halves it. After \(x\) iterations about \(\frac{n}{2^x}\) items are left. One iteration is one pass through the loop body. The worst case is a \(k\) that makes the loop run as many times as possible.

  1. \(\frac{n}{2^x} = 1\) means \(2^x = n\). For the loop counts, write down the gaps: \(n, \lfloor n/2\rfloor, \dots, 1\). Each gap is one iteration.
  2. \(2^{20} = 1{,}048{,}576\). Is \(1{,}000{,}000\) above or below that?
  1. \(2^{12} = 4096\), so \(x = 12\).
  2. For \(n = 2^{20}\), the gaps are \(2^{20}, 2^{19}, \dots, 2^0 = 1\). That's 21 gaps, so 21 iterations. The loop still runs when the gap is 1.
  3. For \(n = 10^6\): \(2^{19} = 524{,}288 \le 10^6 < 2^{20}\), so \(\lfloor\log_2 10^6\rfloor = 19\) and the worst case is \(19 + 1 = 20\).
  4. 12; 21; 20. All are \(\lfloor\log_2 n\rfloor + 1\), which is \(\Theta(\log n)\).

2. The base of the log

This practices the lecture's claim that the base of a log doesn't matter inside \(O(\,)\). The tool is the change-of-base rule: \(\log_c n = \frac{\log_2 n}{\log_2 c}\), so changing the base only divides by a constant.

  1. \(\log_2 8\) is a small whole number.
  2. For the last two, the ratio of the two functions is a constant both ways round. What does that give you for \(c\)?
  1. \(\log_2 8 = 3\), so \(\log_8 n = \frac{\log_2 n}{3}\).
  2. At \(n = 2^{30}\): \(\frac{30}{3} = 10\). Check: \(8^{10} = 2^{30}\).
  3. \(\log_5 n = \frac{1}{\log_2 5}\log_2 n \le 1\cdot\log_2 n\), so \(c = 1\) works. And \(\log_2 n = (\log_2 5)\cdot\log_5 n\), so \(c = \log_2 5 \approx 2.32\) works the other way.
  4. 3; 10; yes; yes. So \(\Theta(\log_5 n) = \Theta(\log_2 n)\): ignore the base.

Proving a bound

Lesson: Proving a bound

3. Prove \(10n + 100 \in O(n^2)\)

This is the lecture's first Big-O proof. It practices the first step of any such proof: choosing the constants. The definition: \(f(n) \in O(g(n))\) when there are constants \(c > 0\) and \(n_0 > 0\) with \(f(n) \le c\cdot g(n)\) for every \(n \ge n_0\). The lecture chose \(c = 10\) and \(n_0 = 10\).

Find your own \(c\) and \(n_0\) with \(10n + 100 \le c\cdot n^2\) for all \(n \ge n_0\). Then find the smallest \(n_0\) that works when \(c = 10\).

  1. With \(c = 10\), divide both sides by 10: you need \(n + 10 \le n^2\).
  2. \(n + 10 \le n^2 \iff 10 \le n(n-1)\). Try \(n = 3\) and \(n = 4\).
  1. With \(c = 10\): \(10n + 100 \le 10n^2 \iff 10 \le n(n-1)\).
  2. \(n(n-1)\) is increasing for \(n \ge 1\), and \(3\cdot2 = 6 < 10 \le 4\cdot3 = 12\). So the smallest \(n_0\) is 4. The lecture uses \(n_0 = 10\), which also works.
  3. Another pair: for \(n \ge 1\), \(10n + 100 \le 10n^2 + 100n^2 = 110n^2\), so \(c = 110, n_0 = 1\).
  4. Any valid pair, e.g. \(c = 10, n_0 = 10\) (the lecture's) or \(c = 110, n_0 = 1\). The smallest \(n_0\) for \(c = 10\) is 4.

4. Prove \(13n^2 - 50n \in \Omega(n^2)\)

This is the lecture's second proof, a lower bound. \(f(n) \in \Omega(g(n))\) is the same definition as \(O\) with the inequality flipped: there are \(c > 0\) and \(n_0 > 0\) with \(f(n) \ge c\cdot g(n)\) for every \(n \ge n_0\). The lecture first tried \(c = 13\), saw it fail, and used \(c = 12\), \(n_0 = 50\).

Find your own \(c\) and \(n_0\) with \(13n^2 - 50n \ge c\cdot n^2\) for all \(n \ge n_0\). Then answer two questions about the choice of \(c\).

  1. Divide both sides by \(n\) (fine for \(n \ge 1\)): you need \(13n - 50 \ge c\cdot n\).
  2. With \(c = 13\) the \(n\)s cancel. What's left?
  1. Equivalent: \(13n - 50 \ge cn\), i.e. \((13 - c)\,n \ge 50\).
  2. \(c = 13\): \(0 \ge 50\) is false for every \(n\), so no \(n_0\) works.
  3. \(c = 12\): \(n \ge 50\), so the smallest \(n_0\) is exactly 50, the lecture's choice.
  4. Any \(c < 13\) with \(n_0 \ge \frac{50}{13 - c}\), e.g. \(c = 12, n_0 = 50\). Smallest \(n_0\) for \(c = 12\): 50. \(c = 13\): impossible. The trade-off: \(c = 1\) needs \(n_0 = 5\), \(c = 11\) needs 25, \(c = 12.5\) needs 100.

5. \(3n^2 + 17 \in \Theta(n^2)\)

This practices the lecture's tight bound, \(\Theta\). \(f \in \Theta(g)\) means both \(f \in O(g)\) (some \(c\), \(n_0\) with \(f(n) \le c\cdot g(n)\) for all \(n \ge n_0\)) and \(f \in \Omega(g)\) (some \(c\), \(n_0\) with \(f(n) \ge c\cdot g(n)\) for all \(n \ge n_0\)). The two pairs don't have to match. Give one pair for each.

  1. The lower bound is the easy one: \(3n^2 + 17\) is never below \(3n^2\).
  2. For the upper bound, \(17 \le 17n^2\) when \(n \ge 1\). Or keep \(c\) small and ask when \(17 \le n^2\).
  1. \(\Omega\): \(3n^2 + 17 \ge 3n^2\) for every \(n\), so \(c = 3, n_0 = 1\).
  2. \(O\): for \(n \ge 1\), \(3n^2 + 17 \le 3n^2 + 17n^2 = 20n^2\), so \(c = 20, n_0 = 1\). Or \(c = 4\): \(3n^2 + 17 \le 4n^2 \iff n^2 \ge 17\), so \(n_0 = 5\).
  3. For example, \(O\) with \(c = 20, n_0 = 1\) (or \(c = 4, n_0 = 5\)), and \(\Omega\) with \(c = 3, n_0 = 1\). So \(3n^2+17 \in \Theta(n^2)\).

6. Write a full proof

This practices turning an intuitive argument into a proof. The lecture justifies \(4 + 3n \in O(n)\) only loosely: "for large inputs, \(4 + 3n < n + 3n = 4n\)". Write a full proof in the shape the lecture used for \(10n + 100 \in O(n^2)\) (problem 3):

  1. Name specific values: "Let \(c = \dots\) and \(n_0 = \dots\)."
  2. Take an arbitrary \(n \ge n_0\).
  3. Show \(4 + 3n \le c\cdot n\) for that \(n\), saying where you use \(n \ge n_0\).

Compare with the solution when you're done.

  1. The justification hints at \(c = 4\). When is \(4 \le n\)?
  1. Let \(c = 4\) and \(n_0 = 4\). Let \(n \ge 4\) be arbitrary.
  2. Since \(n \ge 4\), \(4 + 3n \le n + 3n = 4n = c\cdot n\).
  3. So for all \(n \ge 4\), \(4 + 3n \le 4n\), which proves \(4 + 3n \in O(n)\). (\(c = 7, n_0 = 1\) works too: \(4 \le 4n\) for \(n \ge 1\).) Check that yours names specific values and argues for an arbitrary \(n \ge n_0\); "for large \(n\) it works" is not a proof.

7. Simplest \(\Theta\) classes

This practices the lecture's shortcut for finding a function's \(\Theta\) class: keep only the fastest-growing term and drop its constant factor. Write the simplest class, like n^2 or n log n. These four functions are the lecture's examples.

  1. For each sum, find the term that grows fastest and drop its coefficient.
  2. For the last one, use \(\log(ab) = \log a + \log b\) and \(\log(n^k) = k\log n\).
  1. \(4n + 5\): drop the 5 and the 4. That gives \(n\).
  2. \(0.5n\log n + 2n + 7\): \(n\log n\) dominates \(n\). That gives \(n\log n\).
  3. \(n^3 + 2^n + 3n\): the exponential dominates every polynomial. That gives \(2^n\).
  4. \(n\log(10n^2) = n(\log 10 + 2\log n) = (\log 10)\,n + 2n\log n\). That gives \(n\log n\).
  5. \(\Theta(n)\); \(\Theta(n\log n)\); \(\Theta(2^n)\); \(\Theta(n\log n)\).

Deciding claims, and how far "eventually" is

Lesson: O, Ω, Θ, Proving a bound

8. True or false?

This practices deciding a Big-O claim by asking which side grows faster in the long run. \(f \in O(g)\) means that from some \(n_0\) on, \(f(n) \le c\cdot g(n)\) for one fixed constant \(c\). \(\Theta\) means both \(\le\) and \(\ge\) that way. These five claims are the lecture's. Answer yes if the claim is true, no if it is false.

  1. For each one, ask which side grows faster in the long run. \(O\) means "\(\le\) eventually, up to a constant".
  2. Any exponential \(b^n\) with \(b > 1\) eventually beats any polynomial. And \(3^n / 2^n = 1.5^n\) isn't bounded.
  1. True: for large inputs, \(4 + 3n < n + 3n = 4n\).
  2. False: for any constant \(c\), eventually \(n > c\log n\).
  3. False: for any constant \(c\), eventually \(\log n > c\) (specifically when \(n > 2^c\)).
  4. True: for large \(n\), \(50\log_{1.1} n \le n\).
  5. False: \(3^n \le c\,2^n \iff (\log_2 3)\,n \le \log_2 c + n\), and eventually multiplying by \(\log_2 3\) has more impact than adding \(\log_2 c\).
  6. True, False, False, True, False.

9. How long is "eventually"?

This practices what "eventually" means in a Big-O argument: an inequality may fail for small \(n\), then hold for every \(n\) from some point on. The lecture argued four claims this way, each with "for large \(n\)":

  • \(n^{50} \in O(1.1^n)\): eventually \(n^{50} \le 1.1^n\). (This one is a fact to know, not to compute: it only becomes true at \(n = 4{,}402\). "Eventually" can be far away.)
  • \(3^n \notin O(2^n)\): for any \(c\), eventually \(3^n > c\cdot 2^n\). Below you do the same argument with \(4^n\), so the numbers come out whole. Here \(c = 1000\).
  • \(\log n + 2 \notin O(1)\): for any \(c\), eventually \(\log n + 2 > c\). Here \(c = 12\).
  • \(n + 2\log n \notin O(\log n)\): for any \(c\), eventually \(n + 2\log n > c\log n\). Here \(c = 10\).

Find where "eventually" starts. Use \(\log = \log_2\). Every answer is a whole number you can reach with one or two steps, or by trying powers of 2.

  1. Divide both sides of \(4^n > 1000\cdot 2^n\) by \(2^n\). Since \(4^n = 2^n\cdot 2^n\), you get \(2^n > 1000\).
  2. \(\log n + 2 > 12\) means \(\log n > 10\), so \(n > 2^{10}\).

Worst cases, with \(n\) items stored. "List" means an array or a linked list: both give the same answers.

Unsorted: adding is instant, but finding the smallest means checking everything.

What a heap is

A (min) heap is a binary tree (at most 2 children per node) that follows two rules.

Rule 1, shape: complete

Every level is full except the bottom one, which fills from the left with no gaps.

Why: a complete tree is as short as possible. Each level doubles the room.

height122319

Height counts the edges from the root down to the bottom. A new level starts only when the one above is full: 7 nodes fill height 2, so the 8th starts height 3. Height is about \(\log_2 n\), so a trip from the root to a leaf is short.

Rule 2, order: every node \(\le\) its children

Walk up from any node and the values never get bigger. So the smallest item is always at the root.

But it isn't sorted. The circled 3 sits a level below the circled 5. That's fine: they're in different branches, so 5 isn't above 3.

The rule. Shape keeps the tree short. Order keeps the smallest on top. (A max-heap flips it: every node \(\ge\) its children.)

Why compare only with the parent, never the sibling?

The old parent was already no bigger than the sibling. The new item is smaller than the old parent, so it's smaller than the sibling too, and can take the parent's place. The old parent moves down safely, because it was already no bigger than anything below it.

The answer is the root. To keep the shape, move the bottom-right item up into the root. Then let it sink, swapping with its smaller child, until it's \(\le\) both children. Step through the lecture's recipe:

What a bound leaves open

Key idea. \(f \in O(n)\) only says \(f\) grows at most like \(n\). It doesn't say how small \(f\) is. So a statement about \(f\) is "always true" only if it holds for every function that fits, "always false" if it holds for none, and "sometimes true" otherwise.

The method: test the extremes

Picture the growth classes in a row, slowest first. \(f \in O(n)\) puts \(f\) somewhere from the bottom (a constant, like \(f = 1\)) up to \(n\) (like \(f = n\)). Running times are at least a constant, so that's the whole range.

  1. Try the biggest \(f\) allowed, \(f = n\), and the smallest, \(f = 1\).
  2. If the statement holds for both (and so for everything between), it's always true.
  3. If it fails for both, it's always false.
  4. If one passes and one fails, it's sometimes true.

Suppose \(f(n) \in O(n)\). Pick one of the worksheet's statements. The shaded classes are where \(f\) can be.

    Writing a Big-O proof

    Key idea. A proof of \(f \in O(g)\) declares \(c\) and \(n_0\), takes an arbitrary \(n \ge n_0\), and shows \(f(n) \le c\cdot g(n)\). How you found \(c\) and \(n_0\) is your own scratchwork, and stays out of the proof.

    The shape of a proof

    Show: \(10n + 100 \in O(n^2)\).

    Technique: find \(c > 0\) and \(n_0 > 0\) such that for all \(n \ge n_0\), \(10n + 100 \le c\cdot n^2\).

    The section picks \(n_0 = 6\) where the lecture picked 10. Both work (the smallest that works with \(c = 10\) is 4). The proof never has to say how the numbers were found.

    Proof

    Let \(c = 10\) and \(n_0 = 6\). Show that for all \(n \ge 6\), \(10n + 100 \le 10n^2\).

    \[\begin{aligned} &\equiv n + 10 \le n^2\\ &\equiv 10 \le n^2 - n\\ &\equiv 10 \le n(n-1)\end{aligned}\]

    This is true because \(n(n-1)\) is strictly increasing and \(6(6-1) > 10\).

    Method 1: by parts

    Split \(f\) into terms and bound each term by a multiple of \(g\). Then add.

    Why it works: if \(a(n) \le c_a\, g(n)\) for \(n \ge n_a\) and \(b(n) \le c_b\, g(n)\) for \(n \ge n_b\), then \(a(n) + b(n) \le (c_a + c_b)\, g(n)\) for every \(n\) past both, so use \(c = c_a + c_b\) and \(n_0 = \max(n_a, n_b)\).

    Worksheet 1d: \(7n^2 + 3n \in O(n^4)\).

    Scratchwork: for \(n \ge 1\), \(n^2 \le n^4\) and \(n \le n^4\). So \(7n^2 + 3n \le 7n^4 + 3n^4 = 10n^4\). That suggests \(c = 10\), \(n_0 = 1\).

    Proof

    Let \(c = 10\) and \(n_0 = 1\), and consider an arbitrary \(n \ge n_0\). We have \(7n^2 \le 7n^4\) and \(3n \le 3n^4\), since \(n \ge 1\). Adding these, \(7n^2 + 3n \le 10n^4\), as required.

    By parts is awkward for \(\Omega\). For \(\Omega\) each term would need to be at least a positive multiple of \(g\). A term like \(-8n\) or a constant like \(10\) can never be at least \(c\cdot n^2\), so the split fails. For \(\Omega\), drop the terms that only make \(f\) bigger instead.

    Method 2: the squeeze

    Find a function \(f'\) that sits between them, \(f(n) \le f'(n) \le c\cdot g(n)\), and is easy to compare with both. It's a way to choose \(c\) and \(n_0\); it may not show up in the final proof.

    Worksheet 1e: \(n + 2n\log_2 n \in O(n\log_2 n)\).

    Scratchwork: \(n \le n\log n\) as long as \(\log n \ge 1\), which means \(n \ge 2\). Then \(n + 2n\log n \le n\log n + 2n\log n = 3n\log n\). That's \(f' = 3n\log n\), and \(c = 3\), \(n_0 = 2\) works.

    Proof

    Let \(c = 3\) and \(n_0 = 2\). For an arbitrary \(n \ge n_0\): \(n \le n\log n\) (since \(n \ge 2\), \(\log n \ge 1\)) and \(2n\log n \le 2n\log n\). Adding, \(n + 2n\log n \le c\cdot n\log n\), as required.

    Common mistakes

    • Putting the search for \(c\) and \(n_0\) in the proof. The proof declares them, plugs them in, and explains why the inequality holds.
    • Saying "for large \(n\)" instead of giving a number for \(n_0\).
    • Forgetting where a step needs \(n_0\): "\(n \le n\log n\)" is false at \(n = 1\), which is why 1e's \(n_0\) is 2.

    Writing a \(\Theta\) proof

    Key idea. \(f \in \Theta(g)\) means \(f \in O(g)\) and \(f \in \Omega(g)\). So a \(\Theta\) proof is two proofs, and each one gets its own \(c\) and \(n_0\).

    Worked example: \(2n^2 + 5 \in \Theta(4n^2)\)

    Part 1: \(O\)

    Let \(c = 1\) and \(n_0 = 3\). We show that for all \(n \ge n_0\), \(2n^2 + 5 \le c\cdot 4n^2\).

    Start with the left side. \(2n^2 + 5 \le 3n^2\), because \(n^2 > 5\) whenever \(n \ge 3\). And \(3n^2 \le 4n^2\). So \(2n^2 + 5 \in O(4n^2)\).

    Part 2: \(\Omega\)

    Let \(c = \tfrac12\) and \(n_0 = 1\). We show \(2n^2 + 5 \ge c\cdot 4n^2\).

    \(c\cdot 4n^2 = 2n^2\), and \(2n^2 + 5 \ge 2n^2\) for every positive \(n\). So \(2n^2 + 5 \in \Omega(4n^2)\).

    Since both hold, \(2n^2 + 5 \in \Theta(4n^2)\).

    • Why different constants are fine: the two parts are two separate statements. Each has its own "there exist \(c\) and \(n_0\)".
    • Why the \(O\) part needed \(n_0 = 3\): it trades the \(+5\) for an extra \(n^2\), and \(5 \le n^2\) only from \(n = 3\) on.
    • Why the \(\Omega\) part was easy: dropping the \(+5\) can only make \(f\) smaller, and that's the safe direction for a lower bound.

    Running time of numUnique

    Key idea. Write the running time as a sum over the loops, for the input that makes it largest (worst case) or smallest (best case). Then simplify the sum to a \(\Theta\) class.

    What the method does

    numUnique counts how many different strings an array of length \(n\) holds. For each index it hasn't marked yet, it counts one new string and marks every later copy of it as visited.

    • Lines 3–5 set every entry of visited to false: always \(n\) iterations.
    • Line 7's loop always runs \(n\) times.
    • Line 8 skips an index that was already marked. This is where the input matters.
    • Lines 10–14 run from j = i to the end: \(n - i\) iterations, but only when values[i] is new.

      buildHeap
      
  
      
    
      Key idea. Floyd's buildHeap puts all \(n\) items into the array as given, then calls percolateDown(i) for \(i\) = size down to 1. Working from the bottom up means that when it's \(i\)'s turn, both subtrees under \(i\) are already heaps.
      
  
      

  
      Building a heap from scratch
      
  
      
    
      Suppose you have \(n\) items and want a heap of them. Put them in the array in any order: the shape is already a complete tree, but the order breaks the heap property in many places. Two ways to fix it:
      
    
        
      
      1. Percolate up: insert the items one at a time. Each insert is \(O(\log n)\), so \(O(n\log n)\) in all.
        2. 
      
      2. Percolate down: Floyd's method, below. It's \(\Theta(n)\).
        3. 
    
      
  
      
  
      buildHeap(){
    for(int i = size; i>0; i--){
        percolateDown(i);
    }
}
      

  
      Why this order
      
  
      
    
        
      
      • percolateDown(i) needs heaps below \(i\). It only moves one item. It works when the only thing wrong in \(i\)'s subtree is the item at \(i\) itself.
        • 
      
      • Going from the back guarantees that. Every index below \(i\) is bigger than \(i\), so it was handled earlier. By the time the loop reaches \(i\), both of its subtrees are already heaps.
        • 
      
      • The leaves cost nothing. Indices \(n/2+1\) to \(n\) are leaves: one-node subtrees are already heaps, and percolateDown returns at once. The first index that can move is \(n/2\).

      Why buildHeap is \(\Theta(n)\)
      
  
      
    
      Key idea. A node can only percolate down as far as the height of its subtree, and most nodes sit near the bottom. Adding up "most moves × how many nodes" gives at most about \(n\) moves, so buildHeap is \(\Theta(n)\), not \(\Theta(n\log n)\).
      
  
      

  
      Count by level
      
  
      
    
      "\(n\) calls, each up to \(\log n\)" gives \(O(n\log n)\), which is true but not tight. Count more carefully, by height above the bottom:
      
    
        
      
      • When \(i\) is a leaf: 0 moves. About \(\frac n2\) nodes are leaves.
        • 
      
      • Second-from-last level: at most 1 move. About \(\frac n4\) nodes.
        • 
      
      • Third-from-last level: at most 2 moves. About \(\frac n8\) nodes.
        • 
      
      • …and the root: at most \(\log_2 n\) moves, 1 node.
        • 
    
      
    
      \[0\cdot\frac n2 + 1\cdot\frac n4 + 2\cdot\frac n8 + \dots + \log_2 n\cdot 1 \;=\; n\sum_{i=0}^{\log_2 n}\frac{i}{2^{i+1}} \;\le\; n\sum_{i=0}^{\infty}\frac{i}{2^{i+1}} \;=\; n.\]
      
    
      Each move costs at most two comparisons (one between the children, one with the moving item), so that's at most \(2n\) comparisons: the \(2n\) in the lecture's bound. Either way it's \(O(n)\). And buildHeap has to look at every item at least once, so it's \(\Omega(n)\) too. So \(\Theta(n)\).

      Definitions
      
      
      \(f\in O(g) \iff \exists c>0\ \exists n_0>0\ \forall n\ge n_0:\ f(n)\le c\, g(n)\)
      
      
      \(f\in \Omega(g) \iff \exists c>0\ \exists n_0>0\ \forall n\ge n_0:\ f(n)\ge c\, g(n)\)
      
      
      \(\Theta(g) = O(g)\cap\Omega(g)\). Read them as \(\le\), \(\ge\), \(=\) for large \(n\), up to constants. \(c\) ignores scale; \(n_0\) ignores small inputs.
      
      
      Write \(3n^2+17 \in O(n^2)\) or \(= O(n^2)\), never \(O(n^2) = 3n^2+17\).
      
    
      
    
      
      
      Writing a proof
      
      
        
        
      1. Scratchwork: from \(f(n) \le c\,g(n)\), pick a convenient \(c\), solve for \(n\).
        2. 
        
      2. Proof: "Let \(c = \_\), \(n_0 = \_\). Let \(n \ge n_0\) be arbitrary." Then reversible steps, or a chain of \(\le\).
        3. 
        
      3. If \(c\) fails for every \(n\) (like \(-50 \ge 0\)), change \(c\), not \(n_0\).
        4. 
        
      4. \(\Theta\): an \(O\) proof and an \(\Omega\) proof, each with its own \(c, n_0\).
        5. 
      
      
      
      By parts (for \(O\)): bound each term by \(c_i\,g\), use \(c = \sum c_i\), \(n_0 = \max n_i\). Squeeze: \(f \le f' \le c\,g\).
      
    
      
    
      
      
      Drop / keep
      
      
      Drop: lower-order terms, multiplicative constants, log bases.
      
      
      Keep: exponents (\(n^3 \notin O(n^2)\)), bases of exponentials (\(3^n \notin O(2^n)\)), the logs themselves.
      
      
      \(2^{n+1} = 2\cdot2^n \in \Theta(2^n)\), but \(2^{2n} = 4^n \notin \Theta(2^n)\). Test: is \(f/g\) bounded?
      
    
      
    
      
      
      Growth ladder (slowest first)
      
      
      \(1 \;<\; \log n \;<\; n^{1/10} \;<\; n \;<\; n\log n \;<\; n^2 \;<\; n^3 \;<\; n^{50} \;<\; 1.1^n \;<\; 2^n \;<\; 3^n\)
      
      
      Each is \(O\) of the next but not \(\Omega\) of it.
      
    
      
    
      
      
      Case vs. bound
      
      
      Case (best, worst, average, amortized) picks which function. \(O/\Omega/\Theta\) say what you know about it. Any pairing is allowed. Prefer \(\Theta\) when you know it. Use asymptotics for algorithms, timing for implementations.
      
    
      
    
      
      
      Priority queue ADT
      
      
      insert(item, priority), extract (smallest priority first), isEmpty. Ties: any order.
      
      
      Unsorted array/list: insert \(\Theta(1)\), extract \(\Theta(n)\). Sorted: insert \(\Theta(n)\), extract \(\Theta(1)\). BST: \(\Theta(n)\) both. Heap: \(\Theta(\log n)\) both.
      
    
      
    
      
      
      Binary min-heap
      
      
      Shape: complete tree, height \(\lceil\log_2(n+1)\rceil - 1 \in \Theta(\log n)\). Order: every node \(\le\) its children; min at the root.
      
      
      insert: next open spot, then percolate up (swap with parent while smaller). extract: save root, move last item to root, size−−, percolate down (swap with the smaller child while bigger).
      
      
      Change key (min-heap): decrease → up, increase → down. Max-heap: the reverse.
      
    
      
    
      
      
      Array layout (root at index 1)
      
      
      parent \(i/2\) · left \(2i\) · right \(2i+1\) · leaves \(n/2 + 1\) to \(n\) (integer division). Index 0 unused.
      
      
      buildHeap: for (i = size; i > 0; i--) percolateDown(i); Moves \(\le 0\cdot\frac n2 + 1\cdot\frac n4 + 2\cdot\frac n8 + \dots \le n\): \(\Theta(n)\). Repeated insert: \(\Theta(n\log n)\).
