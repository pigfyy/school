Who wins eventually?

Lecture 3 claims \(n^{50} \in O(1.1^n)\). At \(n = 100\), \(n^{50}\) has 101 digits and \(1.1^{n}\) is about 13,781. So is the claim wrong?

\(n^{50}\)…
vs
\(1.1^{n}\)…

Compared exactly with big integers: \(n^{50} \le 1.1^n \iff n^{50}\cdot 10^n \le 11^n\). The chart's height is the number of digits, so both curves fit on one axis.

The claim is right. \(1.1^n\) loses for a long time, but from \(n = 4{,}402\) on it stays ahead forever. The exact flip happens between 4,401 and 4,402. Big-O doesn't care about the first 4,401 inputs. It asks what happens for all large enough \(n\), and it makes "large enough" precise with two numbers, \(c\) and \(n_0\). That's Lecture 3. Lectures 4 and 5 then use it: a new ADT, the priority queue, and a data structure, the binary heap, that makes both of its operations \(\Theta(\log n)\).

Why binary search is \(\log n\)

Binary search checks the middle of a sorted list, then throws away the half that can't hold the target. Press Step.

Each loop halves what's left: \(16 \to 8 \to 4 \to 2 \to 1\). That's 4 halvings, because \(2^4 = 16\), plus one loop for the last item.

items \(n\)161,024a million
binary search51120
one by one161,024a million

The rule. Halving each loop takes about \(\log_2 n\) loops (worst case). Doubling the list adds just one loop.

The lecture's code 
public static boolean binary_contains(
        List<Integer> a, int k){
    int start = 0;          // k can only be in [start, end)
    int end = a.size();
    while(start < end){     // stop when nothing is left
        int mid = start + (end-start)/2;
        if(a.get(mid) == k)
               return true;
        else if(a.get(mid) < k)
               start = mid+1; // drop mid and the left
        else
               end = mid;     // drop mid and the right
    }
    return false;
}

Buckets: the bigger one loses

Worked example

Algorithm A takes \(10n\) steps. Algorithm B takes \(n^2\). Which is faster?

B is faster at first. From \(n = 10\) on, A is never slower, and the gap keeps growing.

A = 10nB = n²

A bucket is the fastest-growing term, with its constant dropped. \(10n\) is in bucket \(n\), and \(n^2\) is in bucket \(n^2\). For big enough \(n\), the smaller bucket always wins, whatever the constants are.

\(O\), \(\Omega\), \(\Theta\)

Each one compares a step count \(f\) to a simple function \(g\), like \(n\). Here \(f(n) = 2n + 10\) and \(g(n) = n\).

ceiling: 3nf = 2n + 10floor: 2n
in the picturelike
\(f \in O(n)\)\(f\) stays under a ceiling, \(3n\)\(\le\)
\(f \in \Omega(n)\)\(f\) stays over a floor, \(2n\)\(\ge\)
\(f \in \Theta(n)\)both: stuck between them\(=\)

You choose two things. The constant \(c\) in front of \(g\) (3 for the ceiling, 2 for the floor), and where it has to start holding, \(n_0\) (here 10). Before \(n_0\), anything goes. That's how constants and small \(n\) get ignored.

Worked example

Which claims about \(f(n) = 2n + 10\) are true?

  1. \(O(n^2)\)✓\(n^2\) is an even higher ceiling: true, just loose
  2. \(O(n)\)✓ceiling \(3n\), from the picture
  3. \(O(\log n)\)✗\(f\) breaks through any \(c\log n\)
  4. \(\Omega(n)\)✓floor \(2n\), from the picture
  5. \(\Omega(n^2)\)✗\(n^2\) climbs past \(f\), so it can't be a floor
  6. \(\Theta(n)\)✓both \(O(n)\) and \(\Omega(n)\)

  7. The rule. Compare buckets. \(O\): same bucket or a bigger one. \(\Omega\): same or smaller. \(\Theta\): same. When you know the bucket, say \(\Theta\).

Proving a bound

Every \(O\) proof has the same shape. You fill in two numbers, then show one inequality.

The template

Let \(c =\) ? and \(n_0 =\) ?.

Show: for every \(n \ge n_0\), \(f(n) \le c\cdot g(n)\).

algebra, one line at a time, until it's obviously true

This holds for every \(n \ge n_0\).

Worked example

Prove \(2n + 10 \in O(n)\).

  1. pick \(c\)\(c = 3\)just above the 2 in \(2n\)
  2. find \(n_0\)\(2n + 10 \le 3n\)when is this true?
  3. \(10 \le n\)take \(2n\) off both sides, so \(n_0 = 10\)

  4. Fill in the template

    Let \(c =\) \(3\) and \(n_0 =\) \(10\).

    Show: for every \(n \ge 10\), \(2n + 10 \le 3n\).

    \[\begin{aligned} &2n + 10 \le 3n\\ \equiv\ &10 \le n\end{aligned}\]

    This holds for every \(n \ge 10\).

See it

Red dots are where \(2n + 10\) is over \(3n\). Move \(n_0\) to 10 and they drop out.

\(\Omega\): same template, flip to \(\ge\)

Prove \(2n + 10 \in \Omega(n)\)

Let \(c =\) \(2\) and \(n_0 =\) \(1\).

Show: for every \(n \ge 1\), \(2n + 10 \ge 2n\).

\[\begin{aligned} &2n + 10 \ge 2n\\ \equiv\ &10 \ge 0\end{aligned}\]

This holds for every \(n \ge 1\).

Both proofs together give \(2n + 10 \in \Theta(n)\).

Not a proof

  • Checking a few values of \(n\). Argue for any \(n \ge n_0\).
  • A \(c\) that depends on \(n\), like "pick \(c = n\)". \(c\) is one fixed number.

Case vs. bound

Two separate questions. The case (best or worst) picks which inputs you count, which gives one step count. The bound (\(O\), \(\Omega\), \(\Theta\)) says what you know about that count.

Worked example

Linear search checks items left to right until it finds \(k\). On \(n\) items:

whenstepstight
worst\(k\) missing\(n\)\(\Theta(n)\)
best\(k\) first\(1\)\(\Theta(1)\)
  1. worst, \(\Omega(n)\)✓even the worst case takes at least about \(n\)
  2. best, \(O(n)\)✓the best case takes at most \(n\): true, loose
  3. best, \(\Omega(n)\)✗the best case is 1 step

  4. The rule. Any bound goes with any case.

A common mix-up. \(O\) doesn't mean worst case, and \(\Omega\) doesn't mean best case. \(O\) is "at most" and \(\Omega\) is "at least", about whichever case you picked.

Quick check: "Every sorting algorithm takes at least \(n\log n\) time in the worst case." Which pair describes this claim?

Quick check: an algorithm's worst case is \(O(n)\). What does that tell you about its best case?

Why not a list?

kept asinsertextract
unsorted list\(\Theta(1)\)\(\Theta(n)\)
sorted list\(\Theta(n)\)\(\Theta(1)\)
unbalanced BST\(\Theta(n)\)\(\Theta(n)\)

Worst cases, with \(n\) items stored and enough array space set aside. "List" means an array or a linked list: both give the same answers.

Unsorted: adding is instant, but finding the smallest means checking everything.

Sorted: the smallest is right at the end, but adding means making room for it: an array shifts items over, a linked list walks to the spot.

Unbalanced BST (binary search tree): it can turn into one long chain, for example if you insert 1, 2, 3, … in order.

The rule. No order makes extract slow. Full order makes insert slow. A heap keeps just enough order: with a million items, a trip through it is about 20 levels, not a million steps.

What a heap is

A (min) heap is a binary tree (at most 2 children per node) that follows two rules. The top node is the root. A node with no children is a leaf.

Rule 1, shape: complete

Every level is full except the bottom one, which fills from the left with no gaps.

Why: a complete tree is as short as possible. Each level doubles the room.

nodes \(n\)3478a million
height122319

Height counts the edges from the root down to the bottom. A new level starts only when the one above is full: 7 nodes fill height 2, so the 8th starts height 3. Height is about \(\log_2 n\), so a trip from the root to a leaf is short.

Rule 2, order: every node \(\le\) its children

Walking up toward the root, values never get bigger. So the root holds the smallest item.

But it isn't sorted. The circled 3 is smaller than the circled 5, even though it sits lower. That's allowed: the rule only compares a parent with its own children, and these two are in different branches.

The rule. Shape keeps the tree short. Order keeps the smallest on top. (A max-heap flips it: every node \(\ge\) its children.)

Insert: percolate up

Shape first, then order. Drop the new item in the next open spot, then let it climb while it's smaller than its parent. Step through the lecture's recipe, inserting 1.5:

moving itemcomparedjust swapped

The rule. At most one swap per level, so insert is \(O(\log n)\). A new smallest item climbs the whole height, so the worst case is \(\Theta(\log n)\).

Why compare only with the parent, never the sibling?

The old parent was already no bigger than the sibling. The new item is smaller than the old parent, so it's smaller than the sibling too, and can take the parent's place. The old parent moves down safely, because it was already no bigger than anything below it.

Extract: percolate down

The answer is the root. To keep the shape, move the bottom-right item up into the root. Then let it sink: swap it with its smaller child while that child is smaller than it. Stop when no child is smaller, or it has no children. Step through the lecture's recipe:

moving itemcomparedjust swapped

The rule. Swap with the smaller child, so it can be the parent of the other one. At most one swap per level, so extract is \(O(\log n)\). The moved item can sink the whole height, so the worst case is \(\Theta(\log n)\).

Common mistakes

  • Swapping with the larger child, or always the left one.
  • Moving a child up into the empty root instead of the bottom-right item. That leaves a hole in the shape.

What a bound leaves open

All you know is \(f \in O(n)\): \(f\) grows at most like \(n\). It could also be much smaller, even a constant. The shaded buckets are examples of where \(f\) can be. Growth rates in between, like \(\sqrt n\), are possible too.

  6. 2ⁿtoo big

Worked example

\(f \in O(n)\). Is each claim always true, sometimes true, or always false? Try the slowest and fastest \(f\), \(1\) and \(n\). Then give a reason for each "always" or "never".

\(f \in\)\(f = 1\)\(f = n\)true?

Proof by parts

Lecture 3 proved \(2n + 10 \in O(n)\) by solving one inequality. With several terms there's an easier way: make each term bigger until it's a multiple of \(g\), then add them up.

The template

Let \(c =\) ? and \(n_0 =\) ?. Let \(n \ge n_0\) be arbitrary.

each term of \(f\) is \(\le\) a multiple of \(g\), and why

Adding these: \(f(n) \le c\cdot g(n)\). This holds for every \(n \ge n_0\).

Worked example

Prove \(4n^2 + 3n + 5 \in O(n^2)\).

  1. term 1\(4n^2 \le 4n^2\)already a multiple of \(n^2\)
  2. term 2\(3n \le 3n^2\)because \(n \le n^2\) when \(n \ge 1\)
  3. term 3\(5 \le 5n^2\)because \(1 \le n^2\) when \(n \ge 1\)
  4. add\(4n^2 + 3n + 5 \le 12n^2\)\(c = 4 + 3 + 5 = 12\); every step holds from \(n = 1\), so \(n_0 = 1\)

  5. Fill in the template

    Let \(c =\) \(12\) and \(n_0 =\) \(1\). Let \(n \ge 1\) be arbitrary.

    Since \(n \ge 1\): \(4n^2 \le 4n^2\), \(3n \le 3n^2\) and \(5 \le 5n^2\).

    Adding these: \(4n^2 + 3n + 5 \le 12n^2 = c\cdot n^2\). This holds for every \(n \ge 1\).

The rule. Bound each term by a multiple of \(g\). Add the multiples: that's \(c\). Each step holds from some \(n\) on, and the latest start is \(n_0\).

Scratch work stays out. How you found \(c\) and \(n_0\) is scratch work. The proof only states them and shows they work.

Why adding works

If \(a(n) \le c_a\, g(n)\) from \(n_a\) on and \(b(n) \le c_b\, g(n)\) from \(n_b\) on, then \(a(n) + b(n) \le (c_a + c_b)\, g(n)\) once \(n\) is past both. So \(c = c_a + c_b\) and \(n_0 = \max(n_a, n_b)\).

The squeeze

Another way to find \(c\) and \(n_0\): pick a simple middle function \(f'\) that fits between the two, \(f \le f' \le c\cdot g\). It gets squeezed in the middle.

Worked example

Prove \(n^2 + 4 \in O(n^3)\).

  1. pick \(f'\)\(f' = 2n^2\)a multiple of \(f\)'s top (fastest-growing) term, \(n^2\)
  2. \(f \le f'\)\(n^2 + 4 \le 2n^2\)same as \(4 \le n^2\): true from \(n = 2\)
  3. \(f' \le c\cdot g\)\(2n^2 \le 2n^3\)true from \(n = 1\), so \(c = 2\)

  4. The proof

    Let \(c =\) \(2\) and \(n_0 =\) \(2\). Let \(n \ge 2\) be arbitrary.

    Since \(n \ge 2\), \(4 \le n^2\), so \(n^2 + 4 \le 2n^2\). Since \(n \ge 1\), \(n^2 \le n^3\), so \(2n^2 \le 2n^3\).

    So \(n^2 + 4 \le 2n^3 = c\cdot n^3\). This holds for every \(n \ge 2\).

See it

From \(n = 2\) on, each row is at most the row below it. At \(n = 1\), \(f\) is on top, which is why \(n_0 = 2\).

\(\Theta\) proofs

\(f \in \Theta(g)\) means \(f \in O(g)\) and \(f \in \Omega(g)\). So a \(\Theta\) proof is two proofs, each with its own \(c\) and \(n_0\).

The template

\(O\) part. Let \(c =\) ? and \(n_0 =\) ?. Show \(f(n) \le c\cdot g(n)\) for every \(n \ge n_0\).

\(\Omega\) part. Let \(c =\) ? and \(n_0 =\) ?. Show \(f(n) \ge c\cdot g(n)\) for every \(n \ge n_0\).

Both parts hold, so \(f \in \Theta(g)\).

Worked example

Prove \(2n^2 + 5 \in \Theta(4n^2)\).

  1. \(O\): trade the 5\(5 \le n^2\)true from \(n = 3\), since \(3^2 = 9\)
  2. \(2n^2 + 5 \le 3n^2 \le 4n^2\)so \(c = 1\), \(n_0 = 3\)
  3. \(\Omega\): drop the 5\(2n^2 + 5 \ge 2n^2\)dropping it makes \(f\) smaller: safe for \(\ge\)
  4. \(2n^2 = \tfrac12\cdot 4n^2\)so \(c = \tfrac12\), \(n_0 = 1\)

  5. Fill in the template

    \(O\) part. Let \(c =\) \(1\) and \(n_0 =\) \(3\). For \(n \ge 3\), \(5 \le n^2\), so \(2n^2 + 5 \le 3n^2 \le 1\cdot 4n^2\).

    \(\Omega\) part. Let \(c =\) \(\tfrac12\) and \(n_0 =\) \(1\). For \(n \ge 1\), \(2n^2 + 5 \ge 2n^2 = \tfrac12\cdot 4n^2\).

    Both parts hold, so \(2n^2 + 5 \in \Theta(4n^2)\).

The rule. The \(O\) part makes \(f\) bigger: trade small terms for a multiple of the top term. The \(\Omega\) part makes \(f\) smaller: drop terms that only add. The two \(c\)'s can differ, and here they have to.

Quick check: for the \(\Omega\) part, could \(c = 1\) work instead of \(\tfrac12\), with some \(n_0\)? That is, is \(2n^2 + 5 \ge 4n^2\) for every \(n\) from some point on?

    Changing a priority
    
  
    Sometimes an item's priority changes while it waits, like a patient who gets worse. The lecture's operations take the item's index, change its priority, then percolate it up or down.
    

  
    
    
    Worked example
    
    
    In the lecture's heap, the 3 at index 2 becomes 10. Where does the 10 go?
    
    
    
      
      
    1. Index 2 now holds 10 (circled). Above it, \(1 \le 10\): fine. Below it, 4 and 7 are smaller than 10: broken. So percolate down.
      2. 
      
    2. The smaller child is 4, and \(4 < 10\): swap.
      3. 
      
    3. The children are 5 and 9. The smaller is 5, and \(5 < 10\): swap. Index 8 has no children: stop.
      4. 
    
    
  
    

  
    Min-heap: smaller → up; bigger → down.
    
  
    Max-heap: smaller → down; bigger → up.
    
  
    The rule. Only the item's links to its parent and children can break. In a min-heap, a smaller value can only break the link above it, so it climbs. A bigger value can only break the links below it, so it sinks. A max-heap flips both.
    
  
    The lecture also lists remove, which takes out the item at a given index, without going into it.

    Why buildHeap is \(\Theta(n)\)
    
  
    buildHeap calls percolateDown about \(n\) times, and one call can take \(\log n\) swaps. That suggests \(n\log n\). But an item can only sink as far as the bottom, and most nodes are already near it.
    

  
    
    
    Worked example
    
    
    A full tree (every level full) of 15 nodes. Each node shows the most swaps it can make: the number of levels below it.
    
    
    
    
      
    nodes × swaps eachswaps
    
      
    8 leaves × 00
    
      
    4 nodes × 14
    
      
    2 nodes × 24
    
      
    1 root × 33
    
      
    Total11
    
    
    
    
    At most 11 swaps for 15 nodes. "15 calls × 3 swaps" would say 45, but only the root can sink 3 levels, and half the nodes can't sink at all.
    
  
    

  
    The same pattern holds for bigger heaps: most nodes sit near the bottom and can sink only a little.
    
  
    The rule. All the items together can sink fewer than \(n\) levels. Each level costs a fixed amount of work, and each of the \(n/2\) calls adds a fixed amount more, so buildHeap is \(O(n)\). It touches every index, so it's \(\Theta(n)\).
    

  
    
    The lecture's sum
    
    Count level by level from the bottom: about \(\frac n2\) leaves sink 0 levels, \(\frac n4\) nodes sink at most 1, \(\frac n8\) at most 2, and so on up to the root.
    
    
    \[0\cdot\frac n2 + 1\cdot\frac n4 + 2\cdot\frac n8 + 3\cdot\frac n{16} + \dots \;\le\; n\sum_{i=0}^{\infty}\frac{i}{2^{i+1}} \;=\; n.\]
    
    
    The infinite sum adds up to exactly 1. That's at most \(n\) swaps, or \(2n\) comparisons, the lecture's bound.

    Definitions
    
      
    \(f\in O(g) \iff \exists c>0\ \exists n_0>0\ \forall n\ge n_0:\ f(n)\le c\, g(n)\)
    
      
    \(f\in \Omega(g) \iff \exists c>0\ \exists n_0>0\ \forall n\ge n_0:\ f(n)\ge c\, g(n)\)
    
      
    \(\Theta(g) = O(g)\cap\Omega(g)\). Read them as \(\le\), \(\ge\), \(=\) for large \(n\), up to constants. \(c\) ignores scale; \(n_0\) ignores small inputs.
    
      
    Write \(3n^2+17 \in O(n^2)\) or \(= O(n^2)\), never \(O(n^2) = 3n^2+17\).
    
    
    
    
    
      
    Writing a proof
    
      
      
        
    1. Scratchwork: from \(f(n) \le c\,g(n)\), pick a convenient \(c\), solve for \(n\).
      2. 
        
    2. Proof: "Let \(c = \_\), \(n_0 = \_\). Let \(n \ge n_0\) be arbitrary." Then reversible steps, or a chain of \(\le\).
      3. 
        
    3. If \(c\) fails for every \(n\) (like \(-50 \ge 0\)), change \(c\), not \(n_0\).
      4. 
        
    4. \(\Theta\): an \(O\) proof and an \(\Omega\) proof, each with its own \(c, n_0\).
      5. 
      
    
      
    By parts (for \(O\)): bound each term by \(c_i\,g\), use \(c = \sum c_i\), \(n_0 = \max n_i\). Squeeze: \(f \le f' \le c\,g\).
    
    
    
    
    
      
    Drop / keep
    
      
    Drop: lower-order terms, multiplicative constants, log bases.
    
      
    Keep: exponents (\(n^3 \notin O(n^2)\)), bases of exponentials (\(3^n \notin O(2^n)\)), the logs themselves.
    
      
    \(2^{n+1} = 2\cdot2^n \in \Theta(2^n)\), but \(2^{2n} = 4^n \notin \Theta(2^n)\). Test: is \(f/g\) bounded?
    
    
    
    
    
      
    Growth ladder (slowest first)
    
      
    \(1 \;<\; \log n \;<\; n^{1/10} \;<\; n \;<\; n\log n \;<\; n^2 \;<\; n^3 \;<\; n^{50} \;<\; 1.1^n \;<\; 2^n \;<\; 3^n\)
    
      
    Each is \(O\) of the next but not \(\Omega\) of it.
    
    
    
    
    
      
    Case vs. bound
    
      
    Case (best, worst, average, amortized) picks which function. \(O/\Omega/\Theta\) say what you know about it. Any pairing is allowed. Prefer \(\Theta\) when you know it. Use asymptotics for algorithms, timing for implementations.
    
    
    
    
    
      
    Priority queue ADT
    
      
    insert(item, priority), extract (smallest priority first), isEmpty. Ties: any order.
    
      
    Unsorted array/list: insert \(\Theta(1)\), extract \(\Theta(n)\). Sorted: insert \(\Theta(n)\), extract \(\Theta(1)\). BST: \(\Theta(n)\) both. Heap: \(\Theta(\log n)\) both.
    
    
    
    
    
      
    Binary min-heap
    
      
    Shape: complete tree, height \(\lceil\log_2(n+1)\rceil - 1 \in \Theta(\log n)\). Order: every node \(\le\) its children; min at the root.
    
      
    insert: next open spot, then percolate up (swap with parent while smaller). extract: save root, move last item to root, size−−, percolate down (swap with the smaller child while bigger).
    
      
    Change key (min-heap): decrease → up, increase → down. Max-heap: the reverse.
    
    
    
    
    
      
    Array layout (root at index 1)
    
      
    parent \(i/2\) · left \(2i\) · right \(2i+1\) · leaves \(n/2 + 1\) to \(n\) (integer division). Index 0 unused.
    
      
    buildHeap: for (i = size; i > 0; i--) percolateDown(i); Moves \(\le 0\cdot\frac n2 + 1\cdot\frac n4 + 2\cdot\frac n8 + \dots \le n\): \(\Theta(n)\). Repeated insert: \(\Theta(n\log n)\).
