Same ten numbers, five sorts

Section 5 sorts {11, 13, 55, 67, 79, 10, 8, 6, 4, 2}. Insertion sort, selection sort, heap sort, merge sort and quicksort all finish with the same array. Which one compares the fewest pairs of items?

Lecture 12 · slides 3–11 · Mon Oct 26 · Weiss 7.1–7.3

Sorting, and insertion sort

Sorting (slide 4). Input: an array \(A\) of items and a comparison function (for any \(x, y\) we can tell \(x < y\), \(x > y\) or \(x = y\)). Output: a permutation of \(A\) (the same items, maybe reordered) such that \(i \le j\) implies \(A[i] \le A[j]\).

Why sort? It enables binary search, makes some algorithms faster, and is nicer for humans. There's no single best sort: some are faster, some use less memory, some are very fast when the data fits an assumption, and some have other special properties (slide 5).

Properties to consider (slide 10)

Worst-case running time
In placeonly the given array, plus constant extra space
Adaptivefaster as the input gets closer to sorted: linear for a sorted list, nearly linear if nearly sorted
Onlinecan start sorting before the whole list has arrived
Stabletied elements keep their original order

Insertion sort (slides 6–8)

Keep a sorted prefix and extend it by "inserting" the next element: swap the item at index \(i\) with its left neighbour as long as the neighbour is larger. Worst case \(\Theta(n^2)\), best case \(\Theta(n)\).

for (i = 1; i < a.length; i++) {
  j = i;
  while (j > 0 && a[j-1] > a[j]) {
    swap a[j-1] and a[j];
    j--;
  }
}

Insertion sort's properties (slide 11): "except for its asymptotic running time, it has everything you might want." Worst case \(\Theta(n^2)\), with very small constants (nothing is faster for about 50 or fewer items). In place: yes. Adaptive: yes, only out-of-position items move. Online: yes, insert each item as it arrives. Stable: yes, don't swap on a tie.

Quick check: how many swaps does insertion sort make on 10, 9, 8, …, 1?

Teaching notes
  • Slide 7's loop has two slips worth pointing out if students copy it: the swap writes a[prev] = a[i] instead of a[prev] = temp (so nothing is swapped), and it reads a[prev] before checking prev > -1. The version above swaps and checks the bound first.
  • Each swap fixes exactly one out-of-order pair (an inversion), so the number of swaps equals the number of inversions: 0 for sorted input, \(\frac{n(n-1)}{2}\) for reversed.
  • Bubble sort (slide 9) isn't covered: Knuth says it has "nothing to recommend it, except a catchy name".

Lecture 12 · slides 12–30 · Mon Oct 26 · Weiss 7.5

Heap sort

Idea (slide 12). Build a max heap (every node larger than its children), then repeatedly extract the max to fill the sorted list from right to left. Build it with Floyd's buildHeap: working toward the root, percolate each node down.

Extract (slide 15): remove the root, replace it with the last element, and percolate down: if the node is larger than its children, stop; otherwise swap with the larger child and repeat.

Slide 14's max heap, in array order (0-indexed): 10, 9, 6, 8, 7, 5, 2, 4, 1, 3. The first extract takes 10, moves 3 to the root, and percolates it down past 9, 8 and 4.

In place (slides 21–29)

A sort is in place if it uses only \(\Theta(1)\) extra space. Heap sort with a separate heap isn't. The fix: the heap and the sorted list share the array. To extract, swap the root with the heap's last item, then "pretend" the heap is one item shorter.

buildHeap(a);
for (int i = a.length - 1; i >= 0; i--) {
  temp = a[i];
  a[i] = a[0];
  a[0] = temp;
  percolateDown(0);   // within a[0..i-1]
}

Step 0 is the array after buildHeap. Green cells are the sorted part at the end of the array.

Heap sort's properties (slides 20, 30): worst and best case \(\Theta(n\log n)\). In place: yes. Adaptive: no, the running time doesn't depend on the input's order. Online: no, it needs every element in the heap before extracting. Stable: no.

  1. Swaps = out-of-order pairs. For 8: it's bigger than 3, 5, 1 and 2.

Insertion sort on \(n\) items.

  1. Reversed: every pair is out of order. How many pairs are there among 10 items?
  1. Reversed input: item \(i\) swaps \(i\) times: \(0 + 1 + \cdots + 9 = 45 = \frac{10\cdot 9}{2}\).
  2. In general \(\frac{n(n-1)}{2} \in \Theta(n^2)\). Sorted input: one comparison per item, \(\Theta(n)\).
  3. 45; \(\Theta(n^2)\); \(\Theta(n)\).

3. Heap sort by hand

In-place heap sort, 0-indexed max heap (children of \(i\) at \(2i+1\) and \(2i+2\)).

  1. After the first extract the array is 9 8 6 4 7 5 2 3 1 | 10. Swap 9 with the heap's last item (1), then percolate 1 down within the first 8 slots.
  2. Floyd's method: percolate down index 2, then 1, then 0. Each time swap with the larger child.
  1. Swap 9 and 1: 1 8 6 4 7 5 2 3 | 9 10. 1 goes down: swap with 8, then with 7 (8's children are 4 and 7). Result 8 7 6 4 1 5 2 3 9 10.
  2. Build: index 2 (6) has child 4: fine. Index 1 (1) has children 5, 2: swap with 5. Index 0 (3) has children 5, 6: swap with 6; then 3 has child 4: swap. Result 6 5 4 1 2 3.
  3. Every extract percolates down a height of \(\Theta(\log n)\), whatever the input: \(\Theta(n\log n)\) even in the best case.
  4. 8 7 6 4 1 5 2 3 9 10; 6 5 4 1 2 3; \(\Theta(n\log n)\).

4. Which properties?

From slides 11 and 30.

  1. Go through slide 10's definitions one at a time for each sort.
  1. Insertion sort: swaps within the array (in place); each arriving item is inserted into the prefix (online); no swap on a tie (stable).
  2. Heap sort: the heap and the sorted part share the array (in place); same work whatever the order (not adaptive); it needs all items in the heap first (not online).

Lecture 13 · slides 3–14 · Wed Oct 28 · Weiss 7.6

Merge sort

Divide and conquer (slides 4–6). Base case: if the problem is small, solve it directly. Divide: break it into smaller instances. Conquer: solve them recursively. Combine: build the answer from their solutions.

Merge sort (slide 7). Base case: a list of length 0 or 1 is sorted. Divide: split into two halves. Conquer: sort both recursively. Combine: merge the sorted halves.

// slide 10
void ms_helper(myArray, low, high) {
  if (low == high) return;   // base case
  mid = (low+high)/2;
  ms_helper(low, mid);
  ms_helper(mid+1, high);
  merge(myArray, low, mid, high);
}
// slide 11 (the core)
while (l_next <= mid && r_next <= high) {
  if (myArray[l_next] <= myArray[r_next])
    merged[m_next++] = myArray[l_next++];
  else
    merged[m_next++] = myArray[r_next++];
}
// then copy the rest of whichever side remains,
// and copy merged back into myArray[low..high]

Analysis (slides 12–13). Divide: 0 comparisons. Conquer: two lists of size \(\frac n2\). Combine: at most \(n\) comparisons. So \(T(n) = 2T(n/2) + n\): \(n\) work on each of \(\log_2 n\) levels, \(\Theta(n\log n)\). Week 3's tree method, applied.

Properties (slide 14): \(\Theta(n\log n)\) worst case. In place: no, it merges into a second array. Adaptive: no. Online: no. Stable: yes, on a tie take the left element (the <=).

Quick check: slide 8 sorts 5 8 2 9 4 1 3 7. Its last merge combines 2 5 8 9 with 1 3 4 7. How many comparisons does that merge make?

Quick check: what makes merge sort stable?

  • A merge of two runs of length \(k\) makes between \(k\) and \(2k - 1\) comparisons. The last merge here makes 6: it stops when the left run (2 5 8 9) still has 8 and 9 left.

Lecture 13 · slides 15–29 · Wed Oct 28 · Weiss 7.7

Quicksort

Like merge sort: divide and conquer, \(O(n\log n)\) "kind of". Unlike it: the divide step is the hard part, and it's typically faster (slide 15). Divide: pick a pivot \(p\) and partition. Conquer: sort the left and right parts. Combine: nothing to do (slide 16).

Partition (slide 22). Put \(p\) at the beginning. Put Begin just after \(p\) and End at the end. While Begin < End: if Begin's value < \(p\), move Begin right; else swap Begin's value with End's and move End left. When they meet: if the value there is < \(p\), swap \(p\) with it; otherwise swap \(p\) with the value just to its left. Running time \(O(n)\).

Slides 17–20: partition 8 5 7 3 12 10 1 2 4 9 6 11 around 8. Begin passes 5, 7, 3; 12 is swapped to the end; then 11, 10 and 9 are swapped back, and Begin and End meet at 2, which is < 8 (case 1). Swapping 8 with 2 gives

2 5 7 3 6 4 1 8 9 10 11 12

with 8 exactly where it belongs, index 7.

Each step is one partition; the orange cell is where its pivot landed.

Running time (slides 25–27). If the pivot is always the median, each partition halves the list: \(T(n) = 2T(n/2) + n \in O(n\log n)\). If it's always at an extreme, the list shrinks by 1: \(T(n) = T(n-1) + n = \sum_{i=1}^{n} i = \frac{n(n+1)}{2} \in \Theta(n^2)\).

Picking a pivot (slide 28). Ideally the median, but finding it in linear time is complicated and slow. In practice: a random value, or the median of three (first, middle and last elements), which takes constant time.

Properties (slide 29): \(\Theta(n^2)\) worst case but "almost always" \(\Theta(n\log n)\), with better constants than merge sort. In place: "kinda" (the recursion uses stack space). Adaptive: no. Online: no. Stable: no, partition's swaps can reorder ties.

Quick check: after partitioning slide 17's array, at what index is the pivot 8?

Quick check: median of three for slide 17's array (first 8, middle index 5, last 11). Which value is the pivot?

Teaching notes
  • Slide 20 shows 10 and 9 in the other order (… 8 10 9 11 12). Following slide 19's last row, where 9 was swapped into index 5 and 10 into index 9, the result is … 8 9 10 11 12. Either way both are on the right of 8, which is what partition promises.
  • Slide 21's case 2 (meeting at a value > \(p\)) is a different array; in that case \(p\) swaps with the value to the left of the meeting point.
  • With ten equal keys every key goes to one side, so each partition only places the pivot: the \(T(n-1) + n\) worst case (Section 5, problem 0).

Lecture 13 · slides 30–38 · Wed Oct 28 · Weiss 7.11

"Linear time" sorting: bucket and radix sort

These sorts use more than the ability to compare: for example, that the list holds only positive integers less than \(k\), or few distinct values. Their running times always have a second term for that assumption, like \(\Theta(n + k)\) (slide 30).

BucketSort (slides 31–33). For integers from 0 to \(k-1\): use each value as an index into an array of \(k\) buckets (say, linked lists), add each item to its bucket, then append the buckets in order. Creating the buckets is \(\Theta(k)\) or \(\Theta(1)\), inserting is \(\Theta(n)\), emptying is \(\Theta(n + k)\). Overall \(\Theta(n + k)\). Not in place, not adaptive, stable.

RadixSort (slides 34–38). BucketSort by each digit, from least significant to most significant, with base \(b\) (the slides use 10; real implementations use larger bases). With largest value \(m\): \(\log_b m\) passes of a bucket sort with \(b\) buckets, so \(\Theta(n\log_b m + b\log_b m)\).

After the 1's pass, the slide-34 numbers read 800 801 401 101 901 121 512 103 323 823 113 255 555 245 018 999. Each later pass keeps that order within a bucket, which is why the bucket sort has to be stable: after the 10's pass, the list is sorted by its last two digits.

When is this better than merge sort? Bucket sort when \(k\) is small compared with \(n \log n\); radix sort when the number of digits \(\log_b m\) is small compared with \(\log n\).

Section 5: hashing

Problem 1 inserts the same six keys four ways; problem 2 compares the strategies. Everything below follows the section slides and the hashing worksheet's official solutions.

Warm-up. Insert every element of a list into an AVL tree. If all \(n\) are unique, each insert is \(O(\log n)\): \(O(n\log n)\). If all are the same, every insert after the first finds the key at the root and just overwrites the value: \(O(n)\).

On the \(i\)th probe, check index \((h(\text{key}) + f(i)) \bmod \text{TableSize}\): linear \(f(i) = i\), quadratic \(f(i) = i^2\), double hashing \(f(i) = i\cdot g(\text{key})\).

Problem 2: double, double, toil and trouble

Double hashing: the first hash picks where to try first; on a collision the second hash sets the step, trying \(1\cdot h_2(\text{key})\), \(2\cdot h_2(\text{key})\), \(3\cdot h_2(\text{key})\), … away from the original spot.

Two cons of quadratic probing: (1) once the table is half full (\(\lambda \ge \frac12\)) you aren't guaranteed a spot; (2) secondary clustering, since keys with the same home resolve the collision identically. With a good second hash, double hashing avoids both.

Open addressingSeparate chaining
Moves a colliding element to a different index. Can use less memory. Linear probing: easiest, but primary clustering and frequent resizing. Quadratic: secondary clustering; finds a spot if \(\lambda < \frac12\). Double hashing: low chance of clustering, but needs another hash function.Puts all elements for an index in a "bucket" there. Easier to implement. More memory for the bucket structures. Average insert/delete/find \(O(1 + \lambda)\); best \(O(1)\), worst \(O(n)\).

Section 5: sorting

Following the section slides and the sorting worksheet's official solutions. The section adds one sort the lectures didn't: selection sort.

Selection sort (section slide 5). Build a sorted part at the front: find the smallest item in the unsorted part and swap it into place at the end of the sorted part. In place; not usually stable (it can be made stable by shifting instead of swapping and picking the left-most minimum). Best and worst case \(O(n^2)\): it scans the whole unsorted part every time.

Problems 0 and 1

1. Hashing 1a: linear probing

Size 10, \(h(k) = k\). Insert 7, 9, 48, 8, 37, 57. Then delete 37, 7, 57 (tombstones), then try to delete 17.

4. Hashing 2: compare the strategies

Describe double hashing; give two cons of quadratic probing; compare open addressing with separate chaining.

  1. The cons: what happens past half full, and what happens to keys that start at the same index?
  1. Double hashing: \(h_1\) gives the first spot; on a collision, step by \(1\cdot h_2\), \(2\cdot h_2\), \(3\cdot h_2\), … from it.
  2. Quadratic probing's cons: no guaranteed spot once \(\lambda \ge \frac12\); secondary clustering. A good \(h_2\) avoids both.
  3. Open addressing: less memory, probing, clustering. Chaining: easier, more memory, average \(O(1 + \lambda)\), worst \(O(n)\).
  4. Both; \(O(1 + \lambda)\); compare your written answer with the steps above.

5. Sorting 0: all keys equal

Every element of the array is the same, e.g. {17, 17, …, 17}. Give each running time.

  1. Which of these can stop early when nothing is out of order? Which one puts every equal key on one side?
  1. Insertion: no item is less than its neighbour, one pass: \(O(n)\).
  2. Selection: always \(n\) scans for the minimum: \(O(n^2)\). Merge: always \(O(n\log n)\).
  3. Quick: nothing is less than the pivot, so every partition puts all the rest on one side: \(O(n^2)\).
  4. \(O(n)\); \(O(n^2)\); \(O(n\log n)\); \(O(n^2)\).

6. Sorting 1: up, then down

Arrays shaped like {11, 13, 55, 67, 79, 10, 8, 6, 4, 2}: increasing, then decreasing, with the first item bigger than the second run's first. Quicksort uses the leftmost element as the pivot.

  1. The second half is reverse sorted. What does that cost insertion sort, and what does it leave for quicksort after the first pivot?
  1. Insertion: the decreasing half moves past at least half the array each time: \(O(n^2)\).
  2. Selection: always \(O(n^2)\). Merge: always \(O(n\log n)\).
  3. Quick: after the first pivot, one side is reverse sorted and each later pivot is an extreme: \(O(n^2)\).
  4. \(O(n^2)\); \(O(n^2)\); \(O(n\log n)\); \(O(n^2)\).

8. Warm-up: filling an AVL tree

fillUniqueTree inserts each of a list's \(n\) elements into an AVL tree (key and value both the element).

  1. When every key is the same, where does each insert find it?
  1. Unique: \(n\) inserts at \(O(\log n)\) each.
  2. All the same: after the first, every insert finds the key at the root and overwrites the value: \(O(1)\) each.
  3. \(O(n\log n)\); \(O(n)\).

Properties

In place: \(\Theta(1)\) extra space. Adaptive: faster on nearly sorted input. Online: can start before all input arrives. Stable: ties keep their order.

Comparison sorts

worstbestin placeadaptiveonlinestable

Selection\(n^2\)\(n^2\)yesnononot usually
Heap\(n\log n\)\(n\log n\)yesnonono
Merge\(n\log n\)\(n\log n\)nononoyes
Quick\(n^2\)\(n\log n\)kindanonono

Recurrences

Merge sort and quicksort with a median pivot: \(T(n) = 2T(n/2) + n \in \Theta(n\log n)\). Quicksort with an extreme pivot: \(T(n) = T(n-1) + n \in \Theta(n^2)\).

Partition

Pivot first; Begin after it, End at the end. Begin value < \(p\): Begin right; else swap with End, End left. Meet at a value < \(p\): swap \(p\) there; otherwise one to the left. \(O(n)\). Median of three: first, middle, last.

Linear-time sorts

Bucket sort, values 0 to \(k-1\): \(\Theta(n + k)\), stable, not in place. Radix sort, base \(b\), max \(m\): bucket by each digit, least significant first; \(\Theta(n\log_b m + b\log_b m)\).

Hashing (Section 5)

Probe \(i\): \((h + f(i)) \bmod\) size, with \(f(i) = i\), \(i^2\) or \(i\cdot g(k)\). Tombstones don't stop a search. Chaining average \(O(1 + \lambda)\). Quadratic: secondary clustering, needs \(\lambda < \frac12\).
