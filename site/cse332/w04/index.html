Lecture 11 · Fri Oct 23

Room in the table, nowhere to go

Slide 29 inserts 76, 40, 48, 5, 55 and 47 into a table of size 7 with quadratic probing. After five inserts, two slots are still empty. Where does 47 go?

Nowhere. 47 % 7 = 5, and quadratic probing tries \(5 + i^2\): indices 5, 6, 2, 0, 0, 2, 6, … The empty slots are 1 and 4, and \(i^2 \bmod 7\) is only ever 0, 1, 2 or 4, so the probe path never reaches them. Slide 30's guarantee needs a prime table size and \(\lambda < \frac12\). Here \(\lambda = \frac57\). Fixing that is rehashing.

Lecture 9 · slides 3–30 · Mon Oct 19 · Weiss 4.4

AVL insert, start to finish

Slides 3–27 repeat Friday's material: the balance rule, the slide-32 and slide-39 inserts, the two single rotations, and the double rotations. Week 3's pages cover them in detail. Here is the summary, then the new example.

Insert summary (slide 27). Do a BST insert, then update the heights of the new node's ancestors, from the leaf up. At the deepest unbalanced node:

  • LL (left subtree of the left child): rotate right.
  • RR (right subtree of the right child): rotate left.
  • LR (right subtree of the left child): rotate left at the left child, then right at the node.
  • RL (left subtree of the right child): rotate right at the right child, then left at the node.

Done after reaching the root or applying one case.

Insert 1, 2, 5, 3, 4 (slides 28–29)

Inserting 5 makes 1 unbalanced: right, then right, so RR and a left rotation at 1, giving 2 with children 1 and 5. Then 3 goes to 5's left, which is fine. Then 4 goes to 3's right, and 5 is unbalanced: from 5 the key went left (to 3), then right. That's LR: rotate left at 3, then right at 5. The slide's three arrows are exactly these three rotations. Result: 2 with children 1 and 4; 4 with children 3 and 5.

// slide 30
insertHelper(key, value, root) {
  if (root == null) return new Node(key, value);
  if (root.key < key) root.right = insertHelper(key, value, root.right);
  else root.left = insertHelper(key, value, root.left);
  if (isUnbalanced(root)) root = rotate(root);
  return root;
}

The recursion unwinds from the new leaf up, so the first unbalanced node it meets is the deepest one.

Quick check: when 4 is inserted, which case applies at 5?

Quick check: how many single rotations does the whole sequence 1, 2, 5, 3, 4 take?

Teaching notes
  • Ask the room to do 1, 2, 5, 3, 4 on paper first (slide 28 has no answers), then step through it. Most people stop after the first rotation and miss that 4 creates a zig-zag.
  • Recall the definition of height for the class: a leaf is 0, an empty subtree −1. Heights are what the code stores and compares.

Lecture 9 · slides 31–35 · Mon Oct 19

Minimal AVL trees

Slide 31 asks: for an AVL tree of height \(h\), what is the minimum number of nodes? With \(h = 0\) it's 1 node; with \(h = 1\) it's 2. In general, take a root, give it one subtree of height \(h - 1\) (it needs one to reach height \(h\)), and make the other as short as the balance rule allows, height \(h - 2\). Both subtrees should themselves be minimal.

\[M(h) = M(h-1) + M(h-2) + 1,\qquad M(0) = 1,\ M(1) = 2.\]

\(h\)012345678910
\(M(h)\)12471220335488143232

Why \(\Theta(\log n)\) (slides 34–35). \(M(h) > F(h)\), the Fibonacci numbers, and \(F(h) \approx \phi^h\) with \(\phi > 1.6\). So an AVL tree of height \(h\) has at least \(\phi^h\) nodes, and at most \(2^{h+1} - 1\). With \(n\) nodes, \(n \ge \phi^h\) gives \(h \le \log_\phi n\): every operation is \(O(\log n)\), and \(\Omega(\log n)\) because even a full tree is that tall.

Quick check: \(M(6)\).

Quick check: the greatest height an AVL tree with 100 nodes can have.

Teaching notes
  • Slide 33 draws the minimal trees without keys. Have students check each one: every node's subtrees differ by exactly 1 or are both empty. Removing any leaf would either shrink the height or break the balance.
  • "Greatest height with \(n\) nodes" = the largest \(h\) with \(M(h) \le n\). For 100 nodes, \(M(8) = 88 \le 100 < 143 = M(9)\), so 8. A full tree with 100 nodes has height 6.

Lecture 10 · Wed Oct 21 · Hashing 1

What this lecture is for

The point. A hash table is a dictionary that keeps its keys in a small array. A hash function turns each key into a number, and the key goes in slot \(\text{hash} \bmod \text{length}\). So insert, find and delete jump straight to one slot: \(\Theta(1)\) on average, where an AVL tree needs \(\Theta(\log n)\).

Five short pages

  1. Turn a key into a slot, and see why two keys can land in the same one. Key to slot
  2. The four properties of a good hash function. Good hash functions
  3. Hash a string so that order matters, and compute it with one loop. Hashing a string
  4. When two keys share a slot, keep a list there. Separate chaining
  5. How full the table is decides how long a find takes. Load factor

Then Lecture 10 practice. Lecture 11 handles collisions without lists.

Lecture 10 · Wed Oct 21

Key to slot

Imagine one giant array with a slot for every possible key: arr[key] = value. Every operation is one array access. The catch is size: a slot for every possible key is far more memory than any computer has.

A hash table keeps that one-jump idea in a small array. A hash function \(h\) turns the key into an integer, and the slot is that integer mod the array's length:

insert(key, value) {
  h = key.hash();
  arr[h % arr.length] = (key, value);
}

Worked example

Caller ID. The key is a phone number as a string; the value is the person. The hash is the number itself: \(h(\text{"2068675309"}) = 2068675309\). The table has 10 slots.

  1. hash\(h = 2068675309\)the phone number as an integer
  2. slot\(2068675309 \bmod 10 = 9\)mod 10 keeps the last digit

  3. "2068675309" and its person go in slot 9. A find for it computes the same slot and looks only there.

The rest of the lecture uses small whole-number keys with \(h(k) = k\), so the slot is just \(k \bmod \text{length}\). Here are 12, 7 and 5 in a table of size 10:

key\(k \bmod 10\)slot
1222
777
555
2222, but 12 is there

The rule. A key's slot is \(h(k) \bmod \text{length}\). There are more possible keys than slots, so two different keys can get the same slot: a collision. A good hash function makes collisions rare, and the table needs a plan for when they happen anyway.

Quick check: the same phone number in a table of 100 slots. Which slot does "2068675309" go in?

Quick check: why not use the giant array with one slot per possible key?

Lecture 10 · Wed Oct 21

Good hash functions

A hash function maps keys to integers. The lecture asks four things of a good one:

propertymeans
consistentEqual keys hash to the same integer, every time.
uniformIt uses every slot of the array, at roughly equal rates.
effectiveDifferent keys rarely hash the same. A small change to the key changes the hash a lot.
efficientIt is fast to compute.

Worked example

A bad hash: \(h(\text{phone})\) is the phone number's first digit. Check it against each property.

  1. consistentyesthe same number always has the same first digit
  2. uniformnono US number starts with 0 or 1, and around here most start with 2
  3. effectiveno"2068675309" and "2068675305" both hash to 2, and so does every 206 number
  4. efficientyesit reads one character

The rule. A good hash is all four. Consistency is not optional: if equal keys could hash differently, find would look in the wrong slot. So when a Java class overrides equals, it must override hashCode to match: if a.equals(b), then a.hashCode() == b.hashCode().

Quick check: you override equals on Point so points with the same x and y are equal, but keep Object's hashCode. What goes wrong in a hash table?

Quick check: \(h(\text{phone})\) picks one of the number's digits at random. Which property does it break that the first-digit hash keeps?

Lecture 10 · Wed Oct 21

Hashing a string

A string \(s = s_0 s_1 \dots s_{m-1}\) is a row of characters, and each character has an ASCII code \(a(s_i)\): a = 97, b = 98, c = 99. The lecture compares four hashes:

hashisbut
\(h_1(s) = a(s_0)\)consistent, efficientevery string starting with the same letter collides
\(h_2(s) = \sum a(s_i)\)consistent, efficient, maybe uniformanagrams collide: order doesn't count
\(h_3(s) = \sum a(s_i)\cdot 31^i\)all four
\(h_4(s) = 2 \cdot h_3(s)\)consistent, efficient, effectivealways even: not uniform

Worked example

Hash the anagrams "ab" and "ba" with \(h_2\) and \(h_3\).

"ab""ba"
\(h_2\)\(97 + 98 = 195\)\(98 + 97 = 195\)
\(h_3\)\(97 + 98 \cdot 31 = 3135\)\(98 + 97 \cdot 31 = 3105\)

\(h_2\) collides; \(h_3\) doesn't, because each position gets its own power of 31.

Computing \(h_3\) with one loop

Powers of 31 are slow to compute one by one. Factor them out instead: \(s_0 + 31\big(s_1 + 31(s_2 + \dots)\big)\). That's a loop from the last character to the first. Step through it on "abc":

1int h = 0;
2for (int i = m - 1; i >= 0; i--) {
3  h = 31 * h + s[i];
4}
  1. start\(h = 0,\ i = 2\)\(m = 3\), so the loop starts at the last character, c
  2. \(i = 2\)\(h = 31 \cdot 0 + 99 = 99\)c is 99
  3. \(i = 1\)\(h = 31 \cdot 99 + 98 = 3167\)b is 98
  4. \(i = 0\)\(h = 31 \cdot 3167 + 97 = 98274\)a is 97. Then \(i = -1\) ends the loop

  5. Same as the sum

    \(h_3(\text{"abc"}) = 97 + 98 \cdot 31 + 99 \cdot 31^2 = 97 + 3038 + 95139 = 98274\).

The rule. Use every part of the key, in a way where order matters, like \(h_3\). Compute it with one multiply and one add per character. (Java's int wraps around for long strings; short strings like these stay exact.)

Quick check: which hash gives "dog" and "god" the same value?

Quick check: which property does \(h_4\) lose compared with \(h_3\)?

Lecture 10 · Wed Oct 21

Separate chaining

Collisions will happen, so each slot holds a chain: a linked list of every key that hashed there. All three operations find the slot, then work on its chain:

The template

i = h(k) % table.length, then on the chain at table[i]:

  • insert: walk the chain. If \(k\) is there, update its value. If not, add \(k\) on the end.
  • find: walk the chain until \(k\) or the end.
  • delete: walk the chain and unlink \(k\).

Worked example

Size 10, \(h(k) = k\). Insert 12, 22, 7, 42, 5, 17. Then find 42 and find 32.

this step's keychain looked at

The rule. Every operation costs one hash plus a walk along one chain. Short chains mean fast operations. If every key landed in one chain, find would walk all \(n\) of them.

Quick check: continue the example and insert 52. How many keys does insert compare 52 with before adding it?

Quick check: a chained table holds \(n\) keys, and a bad hash sends all of them to one slot. What is the \(\Theta\) class of an unsuccessful find?

Lecture 10 · Wed Oct 21

Load factor

The load factor is the number of keys per slot: \(\lambda = \frac{n}{\text{length}}\). With chaining it is also the average chain length.

Worked example

The table from the last page: 6 keys in 10 slots.

  1. \(\lambda\)\(\frac{6}{10} = 0.6\)6 keys, 10 slots
  2. chains\(0, 0, 3, 0, 0, 1, 0, 2, 0, 0\)the length of each slot's chain
  3. average\(\frac{3 + 1 + 2}{10} = 0.6\)the same number: \(\lambda\) is the average chain length

The rule. With a good hash and chains as linked lists:

  • an unsuccessful find walks a whole chain: about \(\lambda\) comparisons;
  • a successful find stops partway: about \(\frac{\lambda}{2}\) comparisons.

To keep that \(\Theta(1)\), pick a constant and make the array bigger whenever \(\lambda\) goes over it (Lecture 11 does this). With chaining, \(\lambda\) can be more than 1: 15 keys in 10 slots is \(\lambda = 1.5\).

Quick check: a chained table has 8 slots and holds 20 keys. What is \(\lambda\)? A fraction or a decimal is fine.

Quick check: with \(\lambda = 1.5\), about how many comparisons does a successful find expect?

Good hash functions

Lesson: Good hash functions

2. The last digit

The worked example tested the first-digit hash. Now \(h(\text{phone})\) is the phone number's last digit, in a table of size 10. Recall: consistent (equal keys, same hash), uniform (every slot used about equally), effective (different keys rarely collide), efficient (fast).

  1. Take each property in turn. Last digits run 0 to 9 about equally often. How many numbers share a last digit?
  1. The same number always ends in the same digit: consistent. Reading one digit is fast: efficient.
  2. Phone numbers end in every digit 0–9 about equally often, so all 10 slots fill evenly: uniform. That's better than the first-digit hash.
  3. Every number ending in 9 collides, such as "2068675309" and "2065550009". Changing any other digit leaves the hash alone: not effective.
  4. yes; yes; no; yes. Uniform alone isn't enough: a good hash uses every part of the key.

Hashing a string

Lesson: Hashing a string

3. "no" and "on"

The lecture's string hashes on the anagrams "no" and "on". ASCII: n = 110, o = 111. \(h_2(s) = \sum a(s_i)\), \(h_3(s) = \sum a(s_i) \cdot 31^i\), \(h_4(s) = 2 \cdot h_3(s)\). The loop is h = 0; for (i = m-1; i >= 0; i--) h = 31*h + s[i];

  1. \(h_3\) of a two-letter string is \(a(s_0) + a(s_1) \cdot 31\). In "no", \(s_0\) is n.
  2. The loop starts at \(i = m - 1\), the last character.
  1. \(h_2\): \(110 + 111 = 221\) for both. A sum ignores order.
  2. The loop on "no" starts at o: \(h = 31 \cdot 0 + 111 = 111\). Then \(h = 31 \cdot 111 + 110 = 3551\).

  4. \(h_4(\text{"no"}) = 7102\), and \(7102 \bmod 10 = 2\). \(h_4\) is always even, and an even number mod 10 is even, so slot 3 is never used.
  5. yes; 111; 3551; 3521; 2; no.

Load factor

Lesson: Load factor

5. Three load factors

Three chained tables of length 10 hold 3, 8 and 15 keys. Assume a good hash. A fraction or a decimal is fine.

  1. \(\lambda = \frac{n}{\text{length}}\). Unsuccessful: the whole chain. Successful: half of it on average.

Section 4: AVL trees

The section reviews the AVL properties, names the four rotation cases on one picture, and plants two full trees. Everything below follows the section slides and the worksheet's official solutions.

AVL tree: a BST (order property) where every node has at most 2 children and its subtrees' heights differ by at most 1 (structural property). Find, insert and delete are \(O(\log n)\), against \(O(h)\) for an unbalanced BST.

Problem 0: the ABCs

Keys must be comparable; values can be any type. An AVL tree beats a HashMap when you need order: iterating keys in sorted order, or finding the next and previous key (EX4 uses this). It beats a plain BST when the input might be sorted, because balancing prevents the degenerate chain.

Problem 1: the rotation picture

\(p\) is the deepest problem node, the left child of \(a\) (whose other subtree is \(V\)). \(p\)'s children are \(b\) (subtrees \(W\), \(X\)) and \(c\) (subtrees \(Y\), \(Z\)).

Inserted intoRotation

\(X\), right of leftdouble left-right
\(Y\), left of rightdouble right-left
\(Z\), right of rightsingle left rotation

Right rotation at \(p\) (insert in \(W\)), slide 13:

a.left = b

1. Problem 0: the ABCs of AVL trees

What are the constraints on the types you can store in an AVL tree? When is an AVL tree preferred over a HashMap?

  1. What does an AVL tree do with keys that a hash table never does?
  1. Keys must be comparable, because every operation compares them. Values can be anything, as in any dictionary.
  2. An AVL tree keeps keys in order: you can iterate in sorted order, or find the next or previous key, cheaply. A hash table scatters them.
  3. Keys comparable; values any type; prefer an AVL tree when you need sorted order (iteration, next/previous key), and over a plain BST when input may be sorted.

2. Problem 1: left rotation references

\(p\) is \(a\)'s left child and the lowest problem node; the insert went into \(Z\) (the right subtree of \(p\)'s right child \(c\)). Rotate left at \(p\). What does each reference become?

  1. After the rotation, \(c\) is where \(p\) was, \(p\) is \(c\)'s left child, and \(Y\) (keys between \(p\) and \(c\)) needs a new parent.
  1. \(c\) replaces \(p\) under \(a\): a.left = c.
  2. \(Y\) = c.left moves to p.right (it holds keys greater than \(p\), less than \(c\)).
  3. \(p\) becomes \(c\)'s left: c.left = p. Then update the heights of \(p\) and \(c\).
  4. a.left = c; p.right = c.left; c.left = p.

3. Problem 2: let's plant an AVL tree

Insert 10, 4, 5, 8, 9, 6, 11, 3, 2, 1, 14 into an empty AVL tree.

  1. After 10, 4, 5 the tree is 5(4, 10). Keep a running drawing with heights.
  2. Rotations happen on inserting 5, 9, 6, 11, 2 and 1.
  1. 5: LR at 10 → 5(4, 10). 8: no rotation. 9: LR at 10 → 5(4, 9(8, 10)).
  2. 6: 5 is unbalanced; the key went right (9) then left (8): RL → 8(5(4, 6), 9(, 10)).
  3. 11: RR at 9 → 10(9, 11) under 8. 3: no rotation. 2: LL at 4 → 3(2, 4). 1: LL at 5 → 3(2(1), 5(4, 6)). 14: no rotation.
  4. LR; RL; 6; 8 3 2 1 5 4 6 10 9 11 14 (root 8, height 3), as in the official solution.

4. Problem 3: MinAVL trees

Draw an AVL tree of height 4 with the minimum possible number of nodes.

  1. Root, a minimal tree of height 3 on one side, a minimal tree of height 2 on the other.
  1. \(M(4) = 1 + M(3) + M(2) = 1 + 7 + 4 = 12\).
  2. Leaves: 3 in the height-3 subtree plus 2 in the height-2 subtree = 5.
  3. 12 nodes, 5 leaves; for example 8(5(3(2(1), 4), 7(6)), 11(10(9), 12)). Any mirror image works too.

Insert 6, 5, 4, 3, 2, 1, 10, 9, 8, 7 into an empty AVL tree.

  1. After 6, 5, 4, 3, 2, 1 (three LL rotations) the tree is 3(2(1), 5(4, 6)).
  2. Inserting 7 makes the root 3 unbalanced. From 3, which way did 7 go twice?

What this lecture is for

The point. Open addressing handles collisions without chains: every key lives in the array itself. When a key's slot is taken, it probes other slots in a fixed order until one is free. Three probe orders, one way to delete, and rehashing to keep the table from filling up.

probe \(i = 0, 1, 2, \dots\) looks at slot \(\big(h(k) +\) \(f(i)\)\(\big) \bmod \text{length}\)

Linear probing fills the blank with \(i\), quadratic probing with \(i^2\), double hashing with \(i \cdot g(k)\).

Linear probing

On a collision, try the next slot, then the one after, wrapping from the end back to slot 0. Insert stops at the first empty slot. Find follows the same path and stops when it finds the key or reaches an empty slot: the key would have gone there, so it isn't in the table.

The template, filled in

probe \(i\) looks at slot \(\big(h(k) +\) \(i\)\(\big) \bmod \text{length}\), for \(i = 0, 1, 2, \dots\)

Worked example

Size 10, \(h(k) = k\). Insert 38, 19, 8, 109, 10. Then find 29.

where this step's key endsprobed and takenempty

The small number under a slot is the probe \(i\) that looked at it.

The rule. Slots 8, 9, 0, 1, 2 are now one solid block. Any key whose home is in the block probes to its end and makes it longer, and a longer block catches more keys. That feedback loop is primary clustering, and it gets bad as \(\lambda\) nears 1. \(\lambda\) can't pass 1: every key needs its own slot.

Quick check: continue the example and insert 20. Which slot does it end in?

Quick check: what is the largest load factor \(\lambda = \frac{n}{\text{length}}\) an open-addressing table can have?

Delete and tombstones

Insert 3, 13, 23, 33, 43 into a size-10 table with linear probing. All five have home slot 3, so they fill slots 3 to 7. Now delete 13 by simply emptying its slot, and look for 43:

Wrong: 43 is in slot 7. The find stopped at the hole that the delete left behind.

Tombstones. Delete leaves a marker (✝) that means "a key was here".

  • find treats a tombstone as taken: it keeps probing past it.
  • insert probes until it finds the key or an empty slot, remembering the first tombstone it passed. If the key isn't there, it goes in that tombstone's slot.

Worked example

The same five inserts. Then delete 13 with a tombstone, find 43, and insert 53.

where this step's key endsprobedtombstone

The other way: fill the hole

Instead of a tombstone, delete can move a later key back into the hole, then fix the hole that move leaves, and so on until an empty slot. A key may move back only if the hole is on its probe path before its current slot. Keys from a different home that sit later in the block can't move into the hole. This works but is harder to get right, so the lecture uses tombstones.

Quick check: a find reaches a tombstone. What does it do?

Quadratic probing

To stop blocks from growing, jump farther each time: 1 slot, then 4, then 9.

The template, filled in

probe \(i\) looks at slot \(\big(h(k) +\) \(i^2\)\(\big) \bmod \text{length}\), for \(i = 0, 1, 2, \dots\)

Worked example

The lecture's example. Size 7, \(h(k) = k\). Insert 76, 40, 48, 5, 55, 47.

where this step's key endsprobed and takenempty

The rule. After length probes the slots repeat, so some empty slots may never be reached: 47 failed with 2 of 7 slots free. If the length is prime and \(\lambda < \frac{1}{2}\), quadratic probing always finds an empty slot within length/2 probes. Here \(\lambda\) was \(\frac{5}{7}\).

It also fixes primary clustering: keys jump away from a block instead of growing it. But keys with the same home still follow the same path. 76, 48 and 55 all start at 6 and walk 6, 0, 3. That's secondary clustering.

Quick check: go back to the table before 47 was tried (76, 40, 48, 5, 55 inserted) and insert 62 instead. Which slot does it end in?

Quick check: slots 1 and 4 were empty. Why did inserting 47 fail?

Double hashing

Secondary clustering happens because the probe path depends only on the home slot. Double hashing uses a second hash function \(g\) to pick each key's step size, so keys with the same home still take different paths.

The template, filled in

probe \(i\) looks at slot \(\big(h(k) +\) \(i \cdot g(k)\)\(\big) \bmod \text{length}\), for \(i = 0, 1, 2, \dots\)

The lecture leaves \(g\) open. Here \(g(k) = 5 - (k \bmod 5)\), which is always 1 to 5: never 0 and never a multiple of 7.

Worked example

The same keys as the quadratic example: size 7, insert 76, 40, 48, 5, 55, 47.

where this step's key endsprobed and takenempty

The rule. 48 and 55 share home 6 but step by 2 and 5: no secondary clustering. And 47 fits this time. When the length is prime and \(g(k)\) is never a multiple of it, the probes visit every slot, so insert fails only when the table is full. \(g(k)\) must never be 0, or every probe would look at the home slot.

Lecture 11 · Fri Oct 23

Rehashing

Every strategy slows down as \(\lambda\) grows. Rehashing keeps \(\lambda\) small: when it gets too big, make a new array about twice as long, with a prime length, and insert every key again. A key's slot is \(h(k) \bmod \text{length}\), and the length just changed, so keys can't stay at their old slot numbers.

Worked example

Linear probing, size 5. Insert 7, 12, 22. Now \(\lambda = \frac{3}{5}\), over the open-addressing limit of \(\frac{1}{2}\): rehash.

where this step's key endsprobed and takenempty

The rule. Rehash when \(\lambda\) passes the limit for the table type, about \(\lambda < 2\) for separate chaining and \(\lambda < \frac{1}{2}\) for open addressing. The new length is about double, and prime.

Primary clustering: filled blocks that grow, because any key landing in a block extends it. Secondary clustering: keys with the same home slot follow the same probe path. Match each strategy to its problem.

Week 4 cheat sheet

Print with Ctrl+P; only this page prints.

AVL insert

BST insert; update heights from the leaf up; at the deepest unbalanced node: LL → rotate right; RR → rotate left; LR → left at the left child, then right; RL → right at the right child, then left. One case, done.

Rotation references (Section 4)

Right at \(p\) (child \(b\)): a.left = b; p.left = b.right; b.right = p. Left at \(p\) (child \(c\)): a.left = c; p.right = c.left; c.left = p. Then fix heights.

Minimal AVL trees

\(M(h) = M(h-1) + M(h-2) + 1\): 1, 2, 4, 7, 12, 20, 33, 54, 88, 143, 232. Greatest height with \(n\) nodes: largest \(h\) with \(M(h) \le n\). \(h \le \log_\phi n\).

Hash functions

Consistent, uniform, effective, efficient. Equal objects must hash the same (override hashCode with equals).

\(h_3(s) = \sum a(s_i)\,31^i\); Horner: h = 31*h + s[i] from the last character.

Separate chaining

Index \(h(k) \bmod\) length; operate on that bucket. \(\lambda = n/\text{length}\). Unsuccessful find \(\approx \lambda\), successful \(\approx \lambda/2\). Keep \(\lambda < 2\).

Open addressing

Linear \(h + i\); quadratic \(h + i^2\); double \(h + i\cdot g(k)\), all mod length. Keep \(\lambda < \frac12\) (and a prime size for quadratic). Delete with tombstones: finds skip them, inserts reuse them.

Linear: primary clustering. Quadratic: secondary clustering. Double hashing avoids both.

Rehashing

New array about twice as long, prime; re-insert every key with \(h(k) \bmod\) new length.

Dictionaries compared

AVL tree\(\Theta(\log n)\) all; keeps order
Hash table\(\Theta(1)\) average, \(\Theta(n)\) worst; no order
Sorted arrayfind \(\Theta(\log n)\), insert/delete \(\Theta(n)\)
