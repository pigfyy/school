Hoare triples and validity

Hoare triple {{ P }} code {{ Q }}

Valid:  Running code from state satisfying P leads to a state satisfying Q.
If run doesn't terminate, then validity makes no claims about it.

Code from last lecture always terminated. What about loops?

Definition: loop invariant

Definition: loop invariant

A loop invariant of while (b) { body } is an assertion that
holds each time the loop checks condition b.

Before the first iteration, between iterations, and after the last.

Inv:

13long sum(int[] a) {
14    long s = 0;
15    int i = 0;
    {{ Inv: 0 <= i and i <= a.length and
            s = a[0] + ... + a[i - 1] }}
16    while (i < a.length) {

Inv: puts I at the condition check, not before the loop

Rule: while loop

{{ P }}
{{ Inv: I }}
while (b) {
    {{ I and b }}
    body
    {{ I }}
}
{{ I and not b }}
{{ Q }}

b is the loop's condition.
I is a claim the programmer supplies.
The triple {{ P }} while ... {{ Q }}
is valid if three checks pass:
(1) P implies I.
(2) The triple {{ I and b }} body {{ I }}
is valid.
(3) I and not b implies Q.

Why these checks

In the figure, every way into the diamond crosses the arrow labeled I

First iteration: P is true, so by (1), I is true

Between iterations: each comes at the end of a pass
If I was true at the one before, the pass began with I and b

So by (2), the pass ended with I

After last iteration: b is false, so I and not b after the loop
By (3), Q is true there

Each check is a step we know

(1) and (3): implications, no code between
Each is a use of the rule of consequence

(2): a triple about the body

Finding the invariant

So far, the invariant of sum has been given to us

Where does an invariant come from?

Finding one takes some creativity

In simple cases: read I off the postcondition
Q says what is true when the loop is done

I says how the loop makes progress toward Q

sum: read I off Q

Q: s = a[0] + ... + a[a.length - 1]

At each condition check, i is the count of elements added so far

So we put i for a.length in Q: the main fact of I
s = a[0] + ... + a[i - 1]

At the exit, i = a.length, so the main fact turns back into Q

sum: the bounds on i

From where i starts and where it stops:
0 <= i: line 15 starts i at 0

i <= a.length: a pass runs only when i < a.length

Check (3) needs the bound i <= a.length

So an invariant has two kinds of facts:
What has been done so far: s = a[0] + ... + a[i - 1]

How far along the loop is: 0 <= i and i <= a.length
