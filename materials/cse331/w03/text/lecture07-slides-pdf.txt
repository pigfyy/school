A triple
 Hoare triple {{ P }} code {{ Q }}: a claim, code, and a claim
   P is its precondition, Q its postcondition
 Valid: every terminating run of the code
   from a state in which P is true
   ends in a state in which Q is true
 A run that never terminates: the definition asks nothing of it
   Whether code terminates is a separate question (Friday)

Stronger and weaker
 Many claims hold at one point: after line 17, t = h, 0 <= t, true
 Think of a claim as the set of states in which it is true
 P implies Q: P's set is inside Q's
   P is the stronger claim, Q the weaker
 Stronger says more, and is true in fewer states
   "Stronger" sounds bigger: easy to get backward
 The weakest claim of all is true; the strongest is false

Which claim to write at a point
 Among the claims that hold there, one implies all the others
   The strongest: exactly the states a run can be in at that point
 Suppose after line 18 we wrote 0 <= t: it holds, but says less
   After line 19 we cannot say what t is in terms of h, m, s
   The argument fails, though the method satisfies its specification
 Forward reasoning keeps the strongest claim at every step
   It weakens a claim only to check it against one someone wrote

Rule: assignment, forward
                    {{ P }}
                    x = e;
                    {{ P[x ↦ x0] and x = e[x ↦ x0] }}

 x is any variable; e any expression that changes no variable
 P[x ↦ x0] is P with every x replaced by x0
   A fresh name for the value x had before the line
   A name that neither the program nor any claim uses
 The claim after the line is the strongest that makes it valid

 Precondition: the client's promise; the implementer may assume it
   Stronger: the client makes more true, the implementer handles less

The rule, read
 A run entering the true branch found b true; the false, b false
   So those facts hold at the top of their branches
 After the if, a run has taken one branch or the other
   It ends with A true, or with B true: the strongest claim is A or B
 Q has to be true whichever branch ran: check Q against both
 An if with no else still has a false branch (Lecture 5)
   It is empty, so B is P and not b

A proof

   Each step justified by a rule, so anyone can check it: a proof

   The steps use the rules
