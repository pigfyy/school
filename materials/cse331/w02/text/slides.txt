Definition

Knowledge

Your job is to deliver code that you know works.

Three ways to gain knowledge:

Testing: run the code on some inputs and check for expected behavior

Tools: type check the code

Reasoning: use logic to convince yourself the code satisfies the spec

Today: testing

Testing

Definition

A test runs code on a chosen input and
compares the actual behavior to the expected behavior.

A test passes when the behaviors match and fails
when they don't match.

How to write a test

Choose an input

Use the specification to figure out the expected behavior

Run the code on the input, and observe the actual behavior

Compare: the test passes if they match, and fails if not

Expected behavior first

Determine the expected behavior before running the code and
observing the actual behavior. (Why?)

Step 1: the input you chose

Unit, integration, end-to-end

Unit test: one method

Integration test: multiple methods working together

End-to-end test: the whole program

Four tips for choosing inputs

Only test allowed inputs
Spec says nothing about disallowed inputs!

Test each method separately
Assume methods you call are correct. They have their own tests.

Test exhaustively when possible
Every allowed input, say when there are 10 or fewer

Cover each case and each boundary
x appears in the range 0 times, 1 time, many times; empty range

What should the test expect?

Input: the array {5, 1, 5, 2, 5}, the whole range, x = 5

The spec allows any return value of 0, 2, or 4

Specification-based tests

Definition

A specification-based test checks only behavior
that the specification promises, so it passes
on every correct implementation.

Implementation-based: checks more than the spec promises

What tests tell us

A test checks for some behavior on one execution

No set of tests guarantees full correctness
Unless we achieve exhaustive testing

Still, testing is a useful tool in the toolbox
