Task 2 — Crosscheck Your Tests

It's hockey season! Kyle Sherman wants to know how many estimated points his favorite forward, Sherman Kyle, will score this season. He has written the following function to help him out.

/**
 * Calculates the total estimated points scored by a forward playing on a
 * line in a 4-line rotation, over a range of shifts in a game. Line k is
 * on the ice for exactly the shifts s with s mod 4 = k.
 *
 * @param startShift         the shift number to begin calculations, inclusive
 * @param endShift           the shift number to end calculations, inclusive
 * @param lineNumber         the forward's line in the rotation (0-based,
 *                           for example, 3 for the "fourth line")
 * @param avgPointsPerShift  the average points the forward scores per shift
 *                           when his line is on the ice
 * @requires 0 <= lineNumber <= 3
 *           0 <= avgPointsPerShift
 *           startShift <= endShift
 * @return the total estimated points scored in that range
 */
public static int totalPoints(int startShift, int endShift,
                              int lineNumber, int avgPointsPerShift) {
    if (lineNumber < 0 || 3 < lineNumber
        || avgPointsPerShift < 0 || endShift < startShift) {
        throw new IllegalArgumentException();
    }

    int totalPoints = 0;
    for (int shift = startShift; shift < endShift; shift++) {
        if (shift % 4 == lineNumber) {
            totalPoints = totalPoints + avgPointsPerShift;
        }
    }

    return totalPoints;
}

  1. Consider the following three tests, A, B, and C, written as one JUnit method. Determine whether together they meet our coverage requirements: statement, branch, and loop coverage. Count only what allowed inputs can reach, as Lecture 5 does. For each kind of coverage, explain which of A, B, and C provide it, alone or together, or what they miss.

    // A
    assertEquals(6, totalPoints(4, 5, 0, 6));

    // B
    assertEquals(12, totalPoints(10, 24, 1, 4));

}

  2. Senior developer Emily peeks over Kyle's shoulder, claiming that while the tests pass, the implementation fails to satisfy the specification under specific inputs. Identify and write out a test case that would reveal this and explain why the current tests failed to catch it.

  3. Now imagine a more complex function with many more lines (maybe a function to calculate total Kraken wins this season). Weigh the pros and cons of using coverage-based testing as your only safety metric. What role does testing actually play if it cannot provide a proof of correctness?

Task 3 — Nothing But Net-Pay

Zach and James have received a scouting report of players, each with a name and a desired salary in millions of dollars. Your job is to implement a method that chooses some players from the scouting report to form a roster whose total salary is within a required range.

  5. How might we overcome the challenge from part (d) and write a unit test that will pass on any correct implementation of buildRoster?

Task 5 — The Reign Remains the Same

Zach and James's co-GM duties have expanded: they also handle kit orders for the Seattle Reign's youth academy. Code snippets A and B below both claim to compute the total cost of ordering one kit (jersey, shorts, socks, etc.) for every team in the academy, given the price of each piece in a kit; both order for t = 4 teams. Zach wrote snippet A; James wrote snippet B. Naturally, neither will admit the other's is also correct.

We will define \(\textsf{cost}(\text{kit})\) to make the invariant more concise.

  • If kit is empty, then \(\textsf{cost}(\text{kit}) = 0\).
  • If kit is not empty, then \(\textsf{cost}(\text{kit})\) = the sum of the elements of kit.

We will also define \(\textsf{mult}(\text{kit}, t)\).

  • If kit is empty, then \(\textsf{mult}(\text{kit}, t)\) returns an empty array.
  • If kit is not empty, then \(\textsf{mult}(\text{kit}, t)\) returns each element of kit \(\cdot\ t\).

We write kit[i:n] for the elements of kit from index i up to, but not including, index n; kit[n:n] is empty. Each invariant below says that the whole equals what is done so far plus what is left: for A the cost of the full order, and for B the cost of one kit, which B multiplies by t at the end.
