                                                                       18
The browser's loop
 The browser runs a loop, as HttpServer does
   Wait for an event (a click, a response), then run its callback
 await cuts a function in two
   The part before runs now, then hands the thread back
   The part after runs later, as a callback, when the promise is kept
 Between the halves, the loop runs what else is ready: a click's post
 One thing at a time, and still never stuck on the network

Who is the client?
  15     * Four kinds of request reach the program:
  16     * GET /                 the page, index.html, as it is on disk
  17     * GET /app.js           the page's program, app.js, as it is on disk
  18     * GET /api/messages the messages posted so far, as JSON
  19     * POST /api/messages adds the message the fields send, then the
  20     *                       messages posted so far, as JSON
app.js is the client; this comment is the specification it calls against

The client sees only what the specification promises: JSON, never the book

Change the JSON's shape and the client breaks, and no compiler says so
