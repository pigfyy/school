What does this program do?

5public class Sum {
6    public static void main(String[] args) {
7        Scanner in = new Scanner(System.in);
8        System.out.println("Enter some numbers.");
9        List<Integer> list = new ArrayList<>();
10        while (in.hasNextInt()) {
11            list.add(in.nextInt());
12        }
13        // (1)
14        System.out.println("Got " + list);
15        int sum = 0;
16        for (int i = 0; i < list.size(); i++) {
17            sum += list.get(i);
18        }
19        // (2)
20        System.out.println("The sum of your list was: " + sum);
21    }
22}

Nothing at all

Enter some numbers.
Got []
The sum of your list was: 0

Type nothing; end the input at once.

The sentence is true of this run, if an empty list has a sum.

Two numbers

Enter some numbers.
2147483647 1
Got [2147483647, 1]
The sum of your list was: -2147483648

A Java int holds only \(-2^{31}\) to \(2^{31} - 1\),

that is, -2147483648 to 2147483647.

The sentence promised the sum.

Every run

  • Run: one execution of a program, on one input
    • 3 4 5 is one, 1 2 3 another, nothing at all a third
  • Our sentence is a claim about every run
    • One run can confirm it only for that run
    • One run where it is false refutes it: a counterexample

Repairing the sentence

The program asks for numbers. It reads whole numbers between \(-2^{31}\) and \(2^{31} - 1\) from the user, in order, until the input ends or the next thing typed is not such a number; anything from that point on is ignored. It prints the numbers it read, then their sum, wrapped around into that same range if the true sum falls outside it.

1 2 three 4: reads 1 and 2, ignores the rest

Nothing typed: Got [] and a sum of 0

2147483647 1: the sum wraps to -2147483648

2147483648 alone: too big for an int, so nothing is read

What a specification is

A specification says what a piece of code must do on every run, as seen from outside it. It says nothing about how the code does it.

One run where it is false refutes it

It never mentions list, sum, or line 15

The code meets it or fails it

  • For a whole program, outside means the user
    • Its specification is a precise version of the user manual

What an assertion is

  • Assertion: a true or false claim about the program's state
    • Its variables and memory, at one point in the program
  • It holds if the claim is true there on every run
    • One run where it is false, and it does not hold
  • Not Java's assert, a print, or a test
    • Those check only the runs you try

Outside and inside

  • Specification: what the user will see
    • Outside the program, on every run
  • Assertions: why the code delivers it
    • Inside the program, at one point, on every run
    • The user never sees them

Reasoning between assertions

{{ P }}
some code
{{ Q }}
  • Before: P holds
  • The code: takes any P state to a Q state
  • After: Q holds
  • Needs only P: whatever came before is summarized by P

A message meant for someone else

Our standard, all quarter

  • Every input a user can produce gets a response
    • One the specification describes
  • A stack trace is never that response
    • It is a message meant for someone else

How do you come to know?

  • Run it: we ran 3 4 5
  • Test it: a word, nothing, the top of the range
    • Can refute a claim about every run, and never confirm it
  • Reason about it: what is true at (1) and (2)
    • Can confirm a claim about every run, if the argument is right
    • An argument can be wrong
    • A test that refutes the claim refutes the argument too
